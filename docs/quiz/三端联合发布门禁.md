# 题库三端联合发布门禁

> 基线：2026-08-13；对应 QF-02、QF-04、QF-54。题库契约为破坏性替换，不允许 Backend、Admin 或 Platform 单独发布不兼容版本。

## 1. 机器契约

唯一契约源是 Backend `app/contracts/quiz.py`，当前版本 `2026-08-13`，52 个 operation（用户端 22、管理端 30）和 14 个明确删除 operation。以下三份 manifest 必须逐字节语义一致：

- Backend：`app/contracts/quiz_contract_manifest.json`
- Admin：`src/contracts/quiz-contract.json`
- Platform：`src/contracts/quiz-contract.json`

manifest 含认证、权限、限流和规范化路径的 SHA-256 指纹。契约变更必须在同一变更窗口重新生成三份文件：

```bash
Backend/.venv/bin/python Backend/scripts/quiz_contract_manifest.py \
  --write Backend/app/contracts/quiz_contract_manifest.json \
  --write Admin/src/contracts/quiz-contract.json \
  --write Platform/src/contracts/quiz-contract.json
```

只同步 manifest 不代表客户端实现完成。门禁还会扫描两个客户端源码，发现 14 个已删除接口中的任意一个即失败。

## 2. 本地与 CI 门禁

快速静态检查：

```bash
Backend/scripts/joint_release_gate.sh check
```

完整检查：

```bash
Backend/scripts/joint_release_gate.sh full
```

`full` 必须顺序通过：

1. 三份 manifest、指纹和旧接口源码扫描；
2. Backend 单测、契约、迁移和备份 CLI；
3. Admin 测试及生产构建；
4. Platform 独立 `typecheck`、`test` 和微信构建。

任一步失败均不得构建发布清单、推送生产标签或切流。Admin 的 Mock E2E、Platform 的仅构建以及 Backend 的单项目绿灯都不能替代联合门禁。

## 3. 发布和回滚

- 三端构建产物写入同一 release ID，记录 Git commit、契约版本、契约 SHA-256、Alembic head 和镜像/小程序包 digest。
- 先完成备份与迁移门禁，再部署 Backend Web/Worker；`/ready`、Redis Worker 来源和 Prometheus 正常后，才在同一窗口发布 Admin 和 Platform。
- 任一客户端未获审核或真机 UAT 未通过时，不得先切换 Backend 到删除旧接口的版本。
- 回滚必须选择同一 release ID 的 Backend/Admin/Platform 组合；数据库决策遵循[备份恢复与发布回滚运行手册](./备份恢复与发布回滚运行手册.md)。
