# 题库监控与告警运行手册

> 基线：2026-08-12；对应 QF-52。本文只描述聚合指标，不记录用户、管理员、题目、答案、对象键或签名 URL。

## 1. 采集入口

Backend 提供 `GET /internal/metrics`，返回 Prometheus text format。该路由不进入公开 OpenAPI，并必须携带独立凭据：

```http
Authorization: Bearer <QUIZ_METRICS_BEARER_TOKEN>
```

生产环境强制 `QUIZ_METRICS_ENABLED=true`，且 `QUIZ_METRICS_BEARER_TOKEN` 至少 32 字符。Token 应由只读 Secret 注入 Backend 与 Prometheus，禁止写入 Compose、Git、日志或告警正文。无 Token/错误 Token 返回 `401`，关闭出口返回 `404`。

采集示例见 `ops/prometheus/quiz-scrape.example.yml`；规则见 `ops/prometheus/quiz-alerts.yml`。指标接口只能通过内网、服务网格或防火墙白名单访问，不能暴露到互联网。

## 2. 指标与标签边界

| 指标 | 用途 |
|---|---|
| `quiz_api_requests_total{surface,method,route,status_code}` | 请求量、5xx 错误率和 429 汇总 |
| `quiz_api_request_duration_seconds{surface,method,route}` | API P95/P99；桶覆盖 300/500/1000 ms 门槛 |
| `quiz_api_in_progress_requests{surface,method,route}` | 当前在途请求 |
| `quiz_worker_ready`、`quiz_worker_info{source}` | Worker 完整、新鲜及指标来源 |
| `quiz_worker_heartbeat_age_seconds` | Worker 心跳年龄；未知为 `-1` |
| `quiz_worker_processor_queue_depth{processor}` | 四类处理器积压 |
| `quiz_worker_processor_failures{processor}`、`quiz_worker_processor_retries{processor}` | Worker 进程生命周期失败/重试计数 |
| `quiz_worker_processor_last_runtime_seconds{processor}` | 最近一次任务耗时；未知为 `-1` |
| `quiz_worker_stuck_processors` | 有积压且处理器心跳过期的数量 |
| `quiz_worker_stats_lag_seconds`、`quiz_worker_stats_lagging` | 聚合统计一分钟 SLA |
| `quiz_worker_exam_timeout_queue_depth` | 到期考试待结算数 |
| `quiz_worker_oss_cleanup_queue_depth` | OSS 过期文件待清理数 |

`route` 只使用冻结模板，如 `/api/quiz/exams/{exam_id}`；未登记路径归入 `_unmatched`。禁止增加用户 ID、管理员 ID、资源 ID、查询参数、题干或异常正文等高基数/敏感标签。

## 3. 冻结告警

| 告警 | 条件 | 持续时间 | 级别 |
|---|---|---:|---|
| `QuizApiHighErrorRate` | 五分钟 5xx 比例 >2%，且有实际流量 | 10 分钟 | page |
| `QuizApiRateLimitedBurst` | 五分钟 429 >30 | 5 分钟 | warning |
| `QuizQuestionListP95Slow` | 列表/统计 P95 >500 ms | 10 分钟 | warning |
| `QuizAnswerSaveP95Slow` | 练习/考试答案保存 P95 >300 ms | 10 分钟 | page |
| `QuizSessionCreateP95Slow` | 练习/考试创建 P95 >1 s | 10 分钟 | warning |
| `QuizWorkerUnavailable` | Worker 未就绪或时序缺失 | 2 分钟 | page |
| `QuizWorkerProcessorStuck` | 卡死处理器数 >0 | 2 分钟 | page |
| `QuizStatsAggregationLag` | 有待聚合数据且水位超过 60 秒 | 2 分钟 | warning |
| `QuizExpiredExamBacklog` | 到期考试持续待结算 | 2 分钟 | page |
| `QuizOssCleanupBacklog` | OSS 清理持续积压 | 10 分钟 | warning |

## 4. 部署和验收

1. 生成随机 Token，分别通过 Secret 注入 Backend 和 Prometheus；Prometheus 文件使用 `0400` 权限。
2. 加载采集 Job 与规则，执行 `promtool check config` 和 `promtool check rules`。
3. 在 Prometheus Targets 确认采集目标为 `UP`，检查 `quiz_worker_info{source="redis"}=1` 与 `quiz_worker_ready=1`。
4. 将 `severity=page` 路由到电话/短信/值班 IM，将 `warning` 路由到值班 IM；接收组、抑制和升级策略由实际 Alertmanager 配置管理。
5. 在隔离 staging 依次验证错误 Token、停止 Worker、制造统计积压、触发 429 和注入可恢复 5xx；保存 Prometheus 查询、告警触发、通知送达、恢复通知和时间戳证据。
6. 告警触发后先看 `/ready`、Worker 任务监控和上述聚合指标；不得通过指标下钻具体用户或答题内容。

仓库当前仅提供采集/规则和应用侧指标。没有实际 Alertmanager/Webhook/值班账号，因此“通知可到达值班渠道”仍必须在部署环境验收，不能以本地测试代替。
