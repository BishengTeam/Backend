# 题库 PostgreSQL 备份、恢复与发布回滚运行手册

> 基线：2026-08-12；对应 QF-53。目标为 PostgreSQL RPO≤24 小时、RTO≤4 小时；破坏性迁移前必须额外备份；至少每季度完成一次隔离恢复演练。

## 1. 不可突破的边界

- 日常备份、破坏性迁移前备份和恢复演练都针对完整业务数据库，不只备份 `quiz_*` 表，避免外键、用户和管理员引用不一致。
- 备份文件、manifest 和恢复报告是敏感运维资产：目录权限 `0700`，文件 `0600`，生产必须再上传到加密、版本化、跨故障域的私有备份存储；不得进入 Git 或公开 OSS。
- `scripts/postgres_backup.py` 不创建、不删除数据库。恢复演练只接受显式 `--confirm-target`，且数据库名必须以 `_restore_drill` 结尾并为空库。
- 禁止在 `wemini_app_dev`、生产业务库或任何未确认数据库上运行 `restore-drill`。测试使用专门创建的 `wemini_app_restore_drill`。
- 迁移失败禁止 `alembic stamp`、禁止跳过 revision。应用发布失败停止切流，数据库迁移是否允许 downgrade 必须先按本手册判断。

## 2. 日常备份与 RPO

数据库 URL 放入权限 `0400` 的文件，格式使用同步 PostgreSQL URL；命令行和日志不会输出凭据：

```bash
BACKUP_DATABASE_URL_FILE=/run/secrets/wemini/backup_database_url \
  .venv/bin/python scripts/postgres_backup.py backup \
  --kind daily \
  --output-dir /srv/wemini/backups/postgresql

.venv/bin/python scripts/postgres_backup.py check \
  --output-dir /srv/wemini/backups/postgresql \
  --max-age-hours 24
```

每次备份生成 PostgreSQL custom-format `.dump` 和同名 `.manifest.json`，写入 SHA-256、Alembic revision、创建/验证时间及目标数据库匿名指纹。成功前会执行 `pg_restore --list`，部分文件不会重命名为正式归档。

systemd 示例位于 `ops/systemd/wemini-postgres-backup.*`：每日 02:15（上海时区）备份，每小时检查 RPO。部署时将非零退出接入现有监控和值班渠道，并配置备份保留/异地复制策略；仓库不替部署平台决定实际保留周期和 KMS。

## 3. 破坏性迁移前门禁

1. 暂停发布窗口，确认当前 `/ready`、Worker 队列和 PostgreSQL 正常。
2. 创建 `pre-migration` 备份并保存返回的 `backup_reference`：

```bash
BACKUP_DATABASE_URL_FILE=/run/secrets/wemini/backup_database_url \
  .venv/bin/python scripts/postgres_backup.py backup \
  --kind pre-migration \
  --output-dir /srv/wemini/backups/postgresql
```

3. 再执行 `check`，将 manifest、SHA-256、异地对象版本和变更单关联。
4. 只有验证完成后，才把返回的非敏感引用传给题库破坏性迁移：

```bash
QUIZ_DESTRUCTIVE_MIGRATION_BACKUP_REF='<backup_reference>' \
  .venv/bin/alembic upgrade head
```

`quiz001` 降级只恢复旧表结构，不恢复已删除数据；降级前同样需要 `QUIZ_DESTRUCTIVE_DOWNGRADE_BACKUP_REF`。数据库备份是数据恢复来源，不要把 Alembic downgrade 当作数据恢复。

## 4. 季度恢复演练

由 DBA 在隔离实例创建空库 `wemini_app_restore_drill`，授予专用恢复账号权限。不要让脚本拥有创建/删除数据库权限。执行：

```bash
BACKUP_DATABASE_URL_FILE=/run/secrets/wemini/restore_drill_database_url \
  .venv/bin/python scripts/postgres_backup.py restore-drill \
  --archive /srv/wemini/backups/postgresql/<archive>.dump \
  --report-dir /srv/wemini/restore-reports \
  --confirm-target wemini_app_restore_drill
```

脚本在恢复前验证 manifest 与 SHA-256、确认真实连接库名和空库；恢复后核对 Alembic revision、15 张冻结题库表以及总耗时。超过 4 小时返回失败。演练仍需人工完成：

1. 在隔离恢复库运行 Backend 只读冒烟和题库 PostgreSQL 测试。
2. 抽查分类、题目、会话快照、考试成绩、导入任务和永久审计计数。
3. 保存 JSON 报告、备份对象版本、执行人、审批人、开始/结束时间、缺陷和修复日期。
4. DBA 按变更单销毁隔离数据库；脚本不会自动删除。

## 5. 发布失败和回滚决策

```text
部署开始
  ├─ 迁移未运行/仅向后兼容 → 停止切流，回滚 Backend/Admin/Platform 到同一契约版本
  ├─ 迁移成功且旧应用兼容 → 回滚三端镜像，保留新数据库 schema，继续只读验证
  └─ 破坏性或旧应用不兼容 → 保持流量关闭
       ├─ 已验证 downgrade 且无需恢复数据 → 使用备份引用执行受控 downgrade
       └─ 数据需恢复/迁移不确定 → DBA 从已验证归档恢复新实例，完成校验后切换
```

- Backend、Admin、Platform 必须以同一契约版本回滚；禁止只回滚一个客户端并继续切流。
- Web 启动容器负责迁移，`quiz-worker` 设置 `RUN_MIGRATIONS=false`，避免并发迁移。
- 回滚后检查 `/health`、`/ready`、Prometheus、Worker 心跳、考试超时队列、统计滞后和 OSS 清理积压。
- 一旦发生数据恢复，原生产库保留只读取证，不在原库上覆盖式试错；DNS/连接切换和最终销毁由 DBA 变更单控制。

## 6. 当前验收边界

仓库已提供备份/RPO/恢复演练工具、单元安全测试、systemd 调度示例和运行手册，但尚未执行生产或生产等价数据库的实际备份上传与季度恢复。只有保存真实归档、恢复报告且确认 RPO/RTO 后，QF-53 才能从 `🧪` 升为 `DONE`。
