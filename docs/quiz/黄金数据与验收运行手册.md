# 题库黄金数据与验收运行手册

本手册对应 `QF-55`。固定数据由
`scripts/quiz_acceptance_fixtures.py` 生成，版本为
`2026-08-12-qf55-v1`，前缀为 `QF55-V1`。生成器不读取凭据、不连接数据库、
Redis 或 OSS，也不会替操作者创建、清空或删除数据库。

## 1. 安全边界

- 只能在可丢弃且已备份的题库测试/UAT 数据库运行。数据库名必须以
  `_test`、`_uat` 或 `_acceptance` 结尾。
- 禁止对 development、staging 或 production 执行黄金数据清理。
- 首选在执行前制作数据库快照，验收后恢复快照；不要依赖宽泛的 `DELETE`。
- 管理员密码、Bearer Token、OSS RAM 凭据不得写进生成目录、日志或截图。
- 真实 OSS 验收必须使用隔离私有 Bucket 和最小权限 RAM 身份。
- 生成目录可删除，但数据库和 OSS 清理由操作者按本手册逐项确认后执行。

## 2. 生成和校验

推荐每轮使用新的临时目录：

```bash
FIXTURE_DIR="$(mktemp -d -t qf55-quiz-acceptance-XXXXXX)"
.venv/bin/python scripts/quiz_acceptance_fixtures.py generate \
  --output "$FIXTURE_DIR"
.venv/bin/python scripts/quiz_acceptance_fixtures.py check \
  --output "$FIXTURE_DIR"
```

输出含以下文件：

| 文件 | 固定内容 | 用途 |
|---|---:|---|
| `categories.json` | 7 个分类 | 三级树、练习、考试和停用分类 |
| `workflow-questions.json` | 20 题 | 10 道练习清错题、10 道考试题 |
| `import-success-5000.json` | 5,000 题 | JSON 最大题量成功导入 |
| `import-success-5000.csv` | 5,000 题 | CSV 最大题量成功导入 |
| `import-validation-errors.json` | 4 行 | 缺失分类与停用分类/批内重复的混合场景；独立内容错误使整批 `validation_failed` |
| `import-validation-errors.csv` | 5 行 | 解析、题型、分类和重复的全量错误 |
| `acceptance-plan.json` | 9 个场景 | 依赖、操作目标、断言和清理边界 |
| `manifest.json` | SHA-256、大小和数量 | 防止人工修改或传输损坏 |

`--force` 只覆盖上述工具自有文件，不删除同目录的操作员记录。不得把 `/`、用户
主目录、Backend 根目录或项目根目录作为输出目录。

在进行任何写操作前运行只读预检。Token 推荐分别写入权限为 `0600` 的临时 Secret
文件，避免进入 shell 历史和进程参数：

```bash
QF55_DATABASE_URL_FILE=/run/secrets/qf55_database_url
.venv/bin/python scripts/quiz_acceptance_preflight.py \
  --fixture-dir "$FIXTURE_DIR" \
  --database-url-file "$QF55_DATABASE_URL_FILE" \
  --confirm-database wemini_app_acceptance \
  --api-base https://quiz-uat.example.com \
  --admin-token-file /run/secrets/qf55_admin_token \
  --super-admin-token-file /run/secrets/qf55_super_admin_token \
  --disabled-admin-token-file /run/secrets/qf55_disabled_admin_token \
  --user-token-file /run/secrets/qf55_user_token \
  --other-user-token-file /run/secrets/qf55_other_user_token
```

预检使用 PostgreSQL 只读事务，校验数据库安全后缀、当前 Alembic 头、15 张题库表、
无残留 `QF55-V1` 数据、无进行中练习/考试/导入、52 个运行时 operation、14 个已删除
接口、HTTP 服务绑定的数据库指纹、管理员权限、两个不同且无题库历史的专用用户、
Redis Worker 心跳和题库私有 OSS ACL。任何一项失败都会在写入前停止。

预检通过后可运行写入型脚本。它还会校验备份 manifest、备份文件 SHA-256、备份所属
数据库指纹和 Alembic 版本；必须显式提供 `--execute`，不会自动清理数据库或 OSS：

```bash
.venv/bin/python scripts/quiz_acceptance_runner.py \
  --execute \
  --fixture-dir "$FIXTURE_DIR" \
  --database-url-file "$QF55_DATABASE_URL_FILE" \
  --confirm-database wemini_app_acceptance \
  --api-base https://quiz-uat.example.com \
  --admin-token-file /run/secrets/qf55_admin_token \
  --super-admin-token-file /run/secrets/qf55_super_admin_token \
  --disabled-admin-token-file /run/secrets/qf55_disabled_admin_token \
  --user-token-file /run/secrets/qf55_user_token \
  --other-user-token-file /run/secrets/qf55_other_user_token \
  --backup-reference 'wemini-postgres-manual-YYYYMMDDTHHMMSSZ-xxxx.dump#sha256=<64位摘要>' \
  --backup-manifest /secure/backups/wemini-postgres-manual-YYYYMMDDTHHMMSSZ-xxxx.dump.manifest.json \
  --report-dir /secure/qf55-reports
```

Runner 自动完成分类负向校验、20 题导入与发布、JSON/CSV 各 5,000 题、两类多错误
原子失败和报告、校验失败重试拒绝、匿名/超级/禁用管理员及用户 Token 错误用于
管理端的边界、私有 OSS 匿名拒绝/短签下载/真实到期拒绝、练习清错/打卡、考试
恢复/409/完成/放弃。报告只保存 ID、状态、计数和请求 ID；不保存 Token、短签 URL、
题干、选项、标准答案或用户作答。Runner 中途失败也会原子写入部分报告，仅保存
失败阶段、异常类型和已完成的脱敏证据，不写入异常正文。真实 60 分钟超时已有
独立 follow-up 命令；双 Worker 竞争/重启和 OSS 七天清理失败重试仍须按下文人工执行。
当前冻结管理员模型只有 `admin/super_admin`，且 `admin` 固定拥有三项题库权限，因此
真实“已登录但无题库权限”账号暂无法构造；`403/40101` 和拒绝审计已由 PostgreSQL/HTTP
集成测试覆盖，若 UAT 必须用真实账号验收，需先单独决策是否扩展 RBAC 角色模型。
脚本会明确标记剩余项为待验收，不能据此把 QF-55
或真实 OSS/Redis 联调标为完成。

## 3. 环境和账号

验收前记录 release ID、Backend/Admin/Platform commit、数据库名、Redis DB、OSS
Bucket/Prefix、Worker 副本数和当前时间。至少准备：

- 普通管理员：实际拥有 `quiz:list`、`quiz:write`、`quiz:import`；
- 超级管理员：验证 `*` 通配，但题库操作不得要求只能是超级管理员；
- 禁用管理员：验证 401；其 Token 必须是账号禁用前签发且验收期间未过期；
- 无题库权限管理员：当前双角色模型无法建立，不得临时绕过数据库角色约束；
- 两个独立微信测试用户：验证资源隔离、唯一活动考试和超时竞争；
- 匿名客户端：验证公开分类和私有题目/OSS 边界。

账号和值只通过环境 Secret、密码管理器或测试平台注入。生成器只在
`acceptance-plan.json` 中声明变量名，不保存其值。

## 4. 固定执行顺序

### 4.1 分类和工作流小题集

1. 按 `categories.json` 的顺序创建分类，先父后子；记录响应 ID 和
   `lock_version`。
2. 验证三个叶子分类深度为 3，再验证第 4 级、自引用和循环移动均失败。
3. 将 `disabled_leaf` 停用。停用必须发生在分类创建完成后。
4. 将 `workflow-questions.json` 作为 JSON 导入任务提交，等 Worker 返回
   `succeeded/20`。
5. 管理端复核后发布这 20 题。练习与考试分类各应恰好有 10 道已发布题。

上述步骤由 `quiz_acceptance_runner.py` 自动执行；本节保留为人工复核清单。

### 4.2 5,000 题与原子失败

分别新建并等待四个任务，不得复用旧任务 ID：

1. `import-success-5000.json`：终态 `succeeded`，三个计数均为 5,000，题目全为
   `draft`。
2. `import-success-5000.csv`：终态与计数同上；两份成功文件题干互不重复，可以
   在同一隔离库依次执行。
3. `import-validation-errors.json`：终态 `validation_failed`、`created_count=0`，
   报告包含每一项分类/重复错误。
4. `import-validation-errors.csv`：终态 `validation_failed`、`created_count=0`，
   报告同时包含解析、题型、分类和重复错误。

对两个失败任务调用人工重试必须被拒绝。对一个人工制造的基础设施
`failed` 任务重试时，任务 ID 和批次键保持不变，成功后不得重复创建题目。

### 4.3 练习清错

1. 用户 A 在 `practice_leaf` 创建 10 题普通练习；记录固定题序。
2. 第一题首次答错，应自动进入错题本；同会话再次答对仍保留。
3. 提交本会话其余题并完成；当天应自动打卡一次。
4. 新建下一场普通练习，目标错题首次答对后才从活动错题中清除。
5. 新客户端重新登录，历史必须包含两次作答快照，个人统计提交后立即一致。

### 4.4 考试四状态和断网

使用 `exam_leaf` 恰好 10 道题，分别产生：

- `in_progress`：保存至少一题后断开客户端，再登录恢复相同题序和版本；不得返回
  标准答案或解析；
- `completed`：含未答题也可主动交卷，重复交卷幂等，按百分制保留一位；
- `timed_out`：由服务端截止和独立 Worker 结算，计入考试统计；
- `abandoned`：保留已保存答案但不生成成绩、不计统计，详情不泄露答案。

用户 B 同时创建到期考试，用两个 Worker 验证 `SKIP LOCKED` 竞争下每场只结算
一次。答案保存使用过期 `lock_version` 时必须返回 HTTP 409/`40201`。

Runner 的主报告会保存用户 B 的待超时考试 ID 和执行前超时场次基线。等待真实
60 分钟截止时间后，保持独立 Worker 正常运行，再执行：

```bash
.venv/bin/python scripts/quiz_acceptance_timeout_followup.py \
  --execute \
  --source-report /secure/qf55-reports/qf55-acceptance-<timestamp>-<id>.json \
  --database-url-file "$QF55_DATABASE_URL_FILE" \
  --confirm-database wemini_app_acceptance \
  --api-base https://quiz-uat.example.com \
  --other-user-token-file /run/secrets/qf55_other_user_token \
  --backup-reference 'wemini-postgres-manual-YYYYMMDDTHHMMSSZ-xxxx.dump#sha256=<64位摘要>' \
  --backup-manifest /secure/backups/wemini-postgres-manual-YYYYMMDDTHHMMSSZ-xxxx.dump.manifest.json \
  --report-dir /secure/qf55-reports
```

该命令重新校验安全库名、备份归属、Alembic 头、报告 SHA-256、API/数据库指纹和
Redis Worker 心跳。它首先用 PostgreSQL 只读查询证明考试已由 Worker 结算为
`timed_out`，再请求 HTTP 详情和个人统计，避免把查询接口的兜底结算误当成 Worker
证据。若 Worker 尚未结算，命令失败且只写脱敏失败报告，不会修改截止时间或直接改库。

### 4.5 权限、OSS 和 Worker

逐项执行 `acceptance-plan.json` 的 `QF55-PERMISSIONS`、
`QF55-OSS-SEVEN-DAY-LIFECYCLE` 和
`QF55-WORKER-RESTART-AND-CONTENTION`：

- 匿名、用户 Token 错误使用、禁用账号、普通管理员和超级管理员均由 Runner 留独立证据；
- OSS 匿名访问失败，短签不超过 300 秒、可下载且到期后失效，签发写脱敏审计，由 Runner 自动验证；
- 将隔离任务的 `expires_at` 调整到清理窗口只允许在专用 UAT 数据库进行；对象删除
  失败后必须可重试；
- 停止一个 Worker 后任务由另一 Worker 恢复，Web 不运行后台循环；Worker 心跳
  过期时 `/ready` 必须失败。

## 5. 证据和清理

每个场景保存开始/结束时间、请求 ID、任务/会话/考试 ID、HTTP 状态与业务码、
终态计数、审计 ID、Worker 日志片段和必要截图。OSS URL、Token、标准答案批量正文
和用户完整作答不得进入报告。

验收结束后：

1. 停止验收客户端和额外 Worker；
2. 确认所有测试任务终态并保存报告；
3. 删除本轮专用 OSS Prefix，复核 Bucket 中没有残留；
4. 首选恢复执行前数据库快照；若只能逐行清理，必须按外键从会话/作答、题目、
   分类的顺序删除且仅匹配 `QF55-V1`；
5. 重新运行非题库冒烟，确认没有误删共享数据；
6. 删除生成目录，并保留 `manifest.json`、脱敏结果和签字记录到验收归档。

固定数据自检可随时独立运行：

```bash
.venv/bin/python scripts/quiz_acceptance_fixtures.py self-check
```

该命令通过只证明黄金数据可确定生成且符合当前解析契约，不证明 PostgreSQL、Redis、
OSS、独立 Worker、Admin E2E 或微信真机已完成真实验收。
