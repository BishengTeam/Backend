# 人社后端 BE-01、BE-05、BE-10、BE-14、BE-16、BE-17、BE-18 实施记录

更新时间：2026-08-14

本文记录 Backend 侧已落地的实现和仍需外部环境提供的验收证据。主 Todo 中旧版“八类材料/单人 ZIP”表述不再作为接口依据，以[数据字典与状态机](./数据字典与状态机.md)为准。

## 已落地

### BE-01：领域模型和迁移

- `renshe_application`、不可变版本、六类材料、初审/外审及更正记录、退款申请、批次导出任务/分卷/考生项、批次清理任务和审计日志模型已注册到 Base。
- 人社迁移 revision 为 `rsh001`，Alembic 当前唯一 head 为 `quiz002`；迁移包含状态、外键、唯一索引、10 GiB 分卷上限和敏感字段清理字段。
- 实名身份证摘要分为历史 `id_card_hash` 和当前占用 `active_id_card_hash`；身份审核驳回会释放当前唯一占用，驳回账号不会阻止其他账号重新提交同一证件。
- `scripts/check_migrations.py --offline-sql` 验证 base→head SQL 可生成；真实 PostgreSQL 升级/降级需要显式测试库。

### BE-05：私有材料存储

- 仅允许身份证正反面、二寸照片、学生证、学信网电子注册表、学信网学历证明六类材料，全部由服务端校验。
- 对象键随机、按用户/版本隔离；本地仅用于 development/test，生产强制私有阿里云 OSS。
- 扩展名、MIME、文件头、大小、来源对象归属和材料完整性均校验；签名 URL 最长 300 秒。

### BE-10：批次级 ZIP 分卷

- 每次重新生成批次全量符合条件考生；每名考生不跨卷。
- 每卷是可独立解压的 ZIP，最大 10 GiB；包含官方报名 Excel、表头版工作经历 Excel 和材料。
- 报名表固定写入“相关专业的在读应届学生”；学校、专业和在读状态仍只由人工审核，软件不自动判定。
- 导出任务记录进度、心跳、失败原因、幂等重试、SHA-256 和下载审计；生成时长无硬上限。

### BE-14：批次级清理

- 批次取消/终结后建立唯一清理运行；初始期限和退款结束后的重算均使用 `RENSHE_CLEANUP_RETENTION_DAYS`。
- 生产配置被代码和 Compose 固定为 30 天，测试环境允许受控缩短；尚缺真实 OSS 清理 UAT 和退款回调联调，不能按新口径标记 `DONE`。
- 活动退款时暂停，退款完成后应重新计算完整保留期；导出运行期间清理不并发删除。
- 清理 Worker 按有界分页扫描到期队列；最早批次被活动导出或并发锁阻塞时，会继续尝试后续批次，避免队列饥饿。
- 清理材料、生成文件和敏感快照，保留最小财务/审计记录；失败可重试且可观测。

### BE-16：审计和脱敏

- 登录、认证审核、报名变更、批次变更、材料访问、导出、复审、退款、管理员账号变更及用户资料导出/变更均写入人社审计表。
- 审计写入边界递归脱敏身份证号、手机号、openid、凭据、地址、OSS URL 等字段；失败操作只记录异常类型，不记录原始令牌、路径或响应正文；列表默认掩码身份证和手机号。

### BE-18：依赖诊断

- `/health` 保留 `checks.database`/`checks.redis` 字符串兼容格式，并新增 OSS、微信登录、微信支付状态及安全 `details`；不会返回密钥、连接串或 Bucket 名称。
- `/ready` 根据环境要求检查依赖；生产会对私有 OSS 做有界只读探针，未就绪返回 HTTP 503，不能切流。
- 生产 Settings 强制校验数据库、Redis、私有 OSS、微信登录和 V3 支付配置；V2 配置不能满足人社支付要求。

## BE-17 质量入口

```bash
.venv/bin/python -m compileall -q app alembic tests
.venv/bin/pytest tests/unit -q
.venv/bin/python scripts/check_renshe_contract.py
.venv/bin/python scripts/check_migrations.py --offline-sql
```

最近一次无数据库环境下的默认质量结果：`491 passed, 153 skipped`（集成数据库用例按缺少显式测试库条件跳过）；支付、公钥配置门禁和订单防回退专项回归为 `77 passed`。

BE-17 同时提供人社 OpenAPI 契约检查（路径、方法、企业接口停用标记和六类材料清单）：

```bash
.venv/bin/python scripts/check_renshe_contract.py
```

真实验收还必须显式提供：

- `TEST_DATABASE_URL` 和 `TEST_DATABASE_URL_SYNC`（独立 PostgreSQL 测试库）；
- 私有 OSS 测试 Bucket、`oss2` SDK 和最小 RAM 凭据；
- 微信登录测试 AppID/Secret；
- 微信支付 V3 商户号、商户证书序列号、商户私钥、API V3 Key、微信支付公钥、公钥 ID 和回调地址。

凭据缺失时只能得到 `BLOCKED` 或明确外部依赖错误，不能把模拟结果标记为成功。当前 V3 JSAPI 下单、支付/退款通知、主动查单和退款代码已经实现；使用真实商户私钥发起的只读查单及微信支付公钥响应验签已通过。仍需生产 HTTPS 通知地址和轮换后的 API V3 Key，完成真实 0.01 元支付、支付通知、退款及退款通知闭环后，才能把 BE-07/08/13 对应验收项标记为 `DONE`。
