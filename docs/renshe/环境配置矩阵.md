# 人社运行环境与配置矩阵

> 版本：2026-08-10。本文只记录配置边界和验收要求，不保存任何真实凭据。

| 配置面 | 开发 | 测试/预发布 | 生产 |
|---|---|---|---|
| `APP_ENV` | `development` | `test` 或 `staging` | `production` |
| PostgreSQL | 可用本地适配器或独立库 | 独立空库；通过 `TEST_DATABASE_URL` / `TEST_DATABASE_URL_SYNC` 提供 | 独立业务库；应用通过内网主机访问。当前联调约定宿主端口为 `3306`，容器内端口仍以 Compose 服务配置为准 |
| Redis | 可用本地实例 | 独立测试实例 | 内网 `redis://` 或 `rediss://`，不得暴露公网 |
| 人社材料 | `RENSHE_STORAGE_TYPE=local` 仅限本地测试 | 推荐私有阿里云 OSS | 强制 `aliyun_oss` 私有 Bucket；四项 OSS 凭据必填 |
| OSS 签名 | 本地模式不生成公网 URL | 最长 300 秒 | 最长 300 秒；预览、下载和导出分卷均留审计 |
| 微信登录 | 可留空，使用模拟客户端测试 | 使用测试 AppID/Secret | `WECHAT_APPID`、`WECHAT_SECRET` 必填 |
| 微信支付 | **已停用**：`/api/payment/*` 一律 410（业务码 40205） | 已停用 | 已停用；不要求、也不读取 V3 凭证。`WECHAT_PAY_ENABLED` 仅作历史兼容，置 true 不会恢复能力 |
| `RENSHE_CLEANUP_RETENTION_DAYS` | 默认 `30`；可使用大于 `0` 且不超过 `30` 的短周期验证幂等逻辑 | 允许通过部署配置临时缩短，以完成真实 OSS 删除 UAT | 固定 `30`；其他值启动失败，业务 API 和批次页面均不得修改 |
| JWT/PII 密钥 | 使用仅供本机的随机值 | 使用独立随机值 | 由密钥管理系统注入；不得提交仓库或镜像 |
| 日志 | 可调试但不得打印身份证、手机号、令牌或 OSS URL | 与生产相同的脱敏策略 | 结构化采集、轮转、告警；不记录请求体和 Authorization |
| 后台任务 | 支付/退款对账 Worker 永不启动；其他任务可手动运行 | 同左 | 导出、清理、订单超时 Worker 独立部署和监控，使用 `/ready` 决定切流；微信支付对账 Worker 已随功能下线 |
| 题库 Worker | 可使用内嵌模式；根 Compose 默认拆为独立 `quiz-worker` | 必须 Web/Worker 分离并使用独立 Redis；验证重启和竞争 | Web 强制 `QUIZ_EMBEDDED_WORKER_ENABLED=false`；独立 Worker 使用 `QUIZ_WORKER_PROCESS=true`，共享 Redis TTL 指标 |
| 题库导入存储 | `QUIZ_IMPORT_STORAGE_TYPE=local` 仅限开发 | 私有隔离 OSS，完成 7 天清理 UAT | 强制私有 `aliyun_oss`，缺少凭据启动失败 |
| 监控出口 | 可用专用本机 Token 调试 | Prometheus 内网采集并验证规则 | `/internal/metrics` 仅内网开放；专用 Secret Token；Alertmanager 路由到真实值班渠道 |

## 启动校验

生产 Settings 在进程导入时拒绝缺少数据库、Redis、私有 OSS 或微信登录的实例。配置错误必须让部署失败，不能通过 `alembic stamp` 或“本地退款成功”绕过。

**微信支付已于 2026-11 停用**：`POST /api/payment/prepay`、`/orders/{id}/sync`、`/callback`、`/refund-callback` 以及仅服务于微信渠道的 `/admin/orders/{id}/refund`、`/admin/nisp/refunds/{id}/reconcile` 一律返回 `410 Gone`（业务码 40205），在鉴权前即被中间件拦截；支付/退款对账 Worker 不再启动。全平台收款与退款只走银行转账：核账由 `POST /admin/orders/{id}/offline-payment/confirm` 完成，退款由认证审批 + `POST /admin/orders/{id}/offline-payment/refund` 登记真实银行流水、时间与凭证。

### 微信支付 V3 公钥模式字段映射（历史存档，已停用）

| 配置 | 材料 | 用途 |
|---|---|---|
| `WECHAT_PAY_CERT_SERIAL_NO` | `apiclient_cert.pem` 的商户证书序列号 | 放入 Authorization 的 `serial_no`，标识商户请求签名私钥 |
| `WECHAT_PAY_PRIVATE_KEY[_FILE]` | `apiclient_key.pem` | 商户请求及小程序调起参数签名；必须保密 |
| `WECHAT_PAY_API_V3_KEY[_FILE]` | 商户平台设置的 32 字节 API V3 Key | AES-256-GCM 解密支付和退款通知；必须保密 |
| `WECHAT_PAY_PUBLIC_KEY[_FILE]` | 商户平台下载的微信支付公钥 PEM | 验证微信 API 响应、支付通知和退款通知签名 |
| `WECHAT_PAY_PUBLIC_KEY_ID` | `PUB_KEY_ID_...` | 出站 `Wechatpay-Serial` 以及入站签名密钥选择 |

以上字段仅用于解释历史部署；当前版本不读取它们。请在新部署中保持 `WECHAT_PAY_ENABLED=false` 并清理历史密钥材料。

## 探针

- `/health` 是存活探针：保留 `checks.database` 和 `checks.redis` 的字符串兼容格式，并返回不含密钥的诊断详情。
- `/ready` 是切流探针：依赖未就绪时返回 HTTP `503`；生产分别对人社材料 OSS 和题库导入 OSS 做只读私有 ACL 探针，返回 `oss` 与 `quiz_oss`，两者不能互相替代。
- `/internal/metrics` 是鉴权采集出口，不属于公开 API；生产 Token 至少 32 字符且必须由 Secret 注入。

## Compose 边界

- 仓库根 `docker-compose.yml` 是本地开发编排，连接宿主 PostgreSQL/Redis；它不再包含用户名、密码或 JWT 等硬编码凭据，启动前从根 `.env.example` 复制并填写本机 `.env`。
- `Backend/docker-compose.yml` 是生产约束参考：自带 PostgreSQL/Redis 健康检查并拆分 Web/Worker，敏感值通过 `${SECRETS_DIR}` 下的只读 Compose secrets 挂载为 `*_FILE`；部署平台仍应换成其原生 Secret 管理。
- test 必须使用 `wemini_app_test` 与显式 `TEST_DATABASE_URL[_SYNC]`；禁止把测试命令指向 `wemini_app_dev`。
- staging 必须采用与 production 相同的 Web/Worker、Redis、私有 OSS、探针和 Prometheus 拓扑，只允许账号、域名、数据库和 Bucket 使用隔离测试资源。
- production 不挂载源代码或本地 `uploads` 作为题库存储，不允许进程内 Redis 限流回退，也不得使用仓库中的示例 Token。

## 测试凭据边界

真实 PostgreSQL、OSS、微信登录和微信支付验收必须使用专用测试账号、测试 Bucket 和测试商户，测试数据与生产隔离。缺少凭据时测试应显示 `skipped`/`BLOCKED`，不能把模拟结果记为生产通过。
