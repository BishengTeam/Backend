# 已毕业学历型报名

适用新配置 `related_major_graduated_degree_v1`：信息安全管理员、四级／中级工、学历型、已取得毕业证。旧项目版本、已发布批次、订单、审核和导出记录不迁移、不覆盖。新发布批次拒绝使用原在读学生规则或其他未适配组合。

旧批次不再新建报名；已有报名仍从“我的报名”继续按原配置办理，不自动失效或退款。后台需先核对历史人员及支付情况，再决定补正或退款处理。

## 启用

1. 部署兼容的新后端、后台、小程序；执行 Alembic 迁移 `rsh004_graduated_degree`。迁移仅增加补正期限、审核清单和材料类型，未替换历史配置。
2. 后台编辑项目，切换至已毕业学历型规则，配置院校及学历范围，保存草稿。项目名称、职业、等级等仍按现有多项目结构管理。
3. 在“导出配置”上传甲方承诺书 PDF／DOCX（≤10 MB）。后台可下载检查；替换模板会清除页面上的原确认状态。小程序下载当前批次冻结版本的模板，再上传本人签字按手印的 JPG／JPEG／PDF 扫描件。
4. 使用模板填报第二版（`reporting_policy.contract_version=2`），填写报送口径版本、附件目录及六类附件名称（不含扩展名）。F列固定“社会人员”，M列由申请人选择实际从事职业，U列固定模板完整学历型条件原文。明确R列使用工作日期、入学日期、工作优先或允许空值，S列是否必填、是否允许0，并勾选已获甲方确认。缺少模板或任一报送规则未确认时只能保留草稿，不允许开放新批次。
5. 新建批次，完成报名、支付、初审、导出、外审联调，以及甲方实际导入测试，再发布。不要把已有报名的批次切换到新配置。

模板放在 `RENSHE_TEMPLATE_DIR`，以内容 SHA-256 命名，不能覆盖旧文件；部署多实例时该目录须使用共享、持久化存储，并保留原有“报名信息.xlsx”和“工作经历.xlsx”。模板不是考生材料，不随报名保留期清理。新项目版本及批次保存模板文件名、哈希和报送配置；运行时验证模板完整性。模板下载均需登录，后台上传需 `content:write`，下载需 `content:read`。

## 报名及审核

- 本人实名通过及身份证绑定校验继续保留。新规则不要求学生身份或学生认证；毕业院校、院校类型、学历、专业、毕业日期、证书编号在本次报名保存、审核。
- 民族、政治面貌由实名资料预填，缺失时在报名表补齐并按模板字典校验。姓名、身份证、性别及出生日期仍来自已验证本人资料，缺失或有误须通过实名更正流程处理。
- 文化程度区分中专、技校、职高、高职、大专、大学本科、硕士、博士，并受原批次学历与院校范围限制。从事职业使用模板的“在校学生／应届毕业生／职工／失业人员／其他”，与本次已毕业学历资格分别核验。
- 参加工作情况、工作日期、入学日期及职业年限按实填写。毕业日期不得替代工作／入学日期；没有填写年限不能自动转成0。无工作经历不允许填正年限；R、S要求只是甲方报送规则，不增加学历型工龄资格门槛。
- 身份证正反面来自本人已验证资料；身份有误须实名更正。报名照片不复用个人资料的二寸照。照片 JPG／JPEG ≤500 KB；其他图片 ≤10 MB，PDF ≤20 MB。后端逐次验证扩展名、MIME、文件头、大小，提交时再次读取校验。
- 毕业证、学历备案表和签字按手印承诺书全部必填；不提供在读或替代材料路径。无法提供既定学历报告的申请人联系管理员，本期不自行放宽。
- 专业按毕业证原文填写。初审人工核验身份、毕业情况、院校学历、专业相关性、学历报告、一寸白底照片、承诺书七项；后端拒绝未完成核验的通过请求。文件存在与格式合格不等于内容或资格已通过。
- 审核请求带预期报名版本 ID，避免页面停留旧版本后误审核新版本。外审通过继续要求当前版本的成功导出记录。
- 驳回选择具体字段／材料并填写原因、带时区的补正截止时间。截止前允许已支付报名在普通报名关闭后补正；退款冻结、报名关闭、批次取消／归档仍阻断。提交产生独立版本，复用原已支付订单。
- 新学历型不使用直接翻转旧审核结论的“更正审核”入口；使用“打回补正→重新初审”保留核验与期限记录。

## 导出与验收边界

新导出器保留甲方25列及原四个工作表（Sheet1、模板示例、模板说明、申报条件），不增加“毕业学历信息”工作表；毕业学历详情保留在报名版本和后台审核中。导出前核对实际模板标题、下拉字典和职业—申报条件联动；民族、政治面貌及其他模板必填项缺失时拒绝导出。M列使用实际职业状态，U列使用完整字典原文（原文含在读应届字样，但本期资格仍仅接受已取得毕业证人员）；R、S按已确认规则输出，数值0不会变成空值。L、X列分别输出实际工作单位和社保参保单位，不虚构填充。

附件按当前报名版本冻结的报送目录和名称输出，包含身份证正反面、一寸照、毕业证、学历备案表、承诺书，扩展名与真实原文件一致，不改后缀伪装格式。历史学生批次仍使用原导出器。旧已毕业学历型版本缺少模板填报信息时阻止新导出，须管理员设置补正期限，由申请人核对同项目最新已确认报送配置后生成新报名版本；学历范围、原批次和已支付订单仍按原配置保留。第二版批次使用本批次冻结口径，不能随项目最新配置变化。旧版本、审核、已完成导出及订单不覆盖；补正后必须重新初审并重新导出。

当前自动化使用隔离 SQLite、私有本地对象存储、测试承诺书及实际甲方报名工作簿验证链路；测试承诺书不代表甲方确认版本。未操作生产数据库，未执行微信真机上传、真实支付或甲方导入。正式验收仍需甲方确认R、S报送规则和承诺书，并测试原工作簿、报送列值、附件目录及文件格式。此次模板填报字段与报送口径保存在现有JSON版本中，无新增数据库迁移。

## 回滚

按批次关闭新报名入口，保留新配置及数据。已有新格式资料时，迁移降级会拒绝删除新增材料类型约束；使用能识别新旧两类配置的兼容版本回滚。不得删除历史版本或自动判定原在读报名失效，业务方另行确认其补正／退款处理。
