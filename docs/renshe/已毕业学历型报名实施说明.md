# 已毕业学历型报名

适用新配置 `related_major_graduated_degree_v1`：信息安全管理员、四级／中级工、学历型、已取得毕业证。旧项目版本、已发布批次、订单、审核和导出记录不迁移、不覆盖。新发布批次拒绝使用原在读学生规则或其他未适配组合。

旧批次不再新建报名；已有报名仍从“我的报名”继续按原配置办理，不自动失效或退款。后台需先核对历史人员及支付情况，再决定补正或退款处理。

资料来源、目录范围及差异说明见[组合目录与资料依据](组合目录与资料依据.md)。

## 启用

1. 暂停创建新导出任务，处理完在途任务后发布兼容的新后端、后台、小程序。执行迁移 `rsh006_current_export`（包含此前的 `rsh005_standard_materials`），只增加任务规则指纹，不重写历史文件或材料。
2. 新增项目须选择有资料依据的职业／工种、技能等级和申报类型；待适配组合可保存草稿但不能启用，职业代码、等级导出值、资格与材料规则由该组合自动带入。当前仅适配信息安全管理员四级／中级工。项目名称、介绍、封面和承诺书模板可维护，资格规则、材料参数及导出配置仍为只读。查看已有项目时按其实际配置展示要求；仅修改名称、介绍或承诺书不会重置职业、等级、原规则或历史批次。
3. 在产品的独立“承诺书模板”区域上传甲方确认的PDF／DOCX（≤10 MB），可查看当前文件、下载或上传替换。保存后供申请人下载当前模板，用户上传本人签字按手印的JPG／JPEG／PDF扫描件。历史规则项目也能直接设置承诺书，不需要切换资格规则才能看到入口。
4. 导出说明仅展示固定25列表、工作经历表实际生成方式、脱敏目录示例、当前报名模板下载及只读字段说明。不提供模板、列映射、目录、文件名、版本号或R／S规则的编辑控件。项目启用仅检查业务资格、材料要求及承诺书文件，不再要求配置任何导出参数或勾选规则确认。
5. 新建批次，完成报名、支付、初审、导出、外审联调，以及甲方实际导入测试，再发布。不要把已有报名的批次切换到新配置。

三个选择框由 `renshe_catalog.combinations()` 提供，区分资料已有依据与实现已适配。新客户端仅提交组合标识及承诺书等业务信息，服务端校验后选取对应规则，不根据项目名称推断职业。已有项目省略配置与选择时保留原配置；存在关联批次的项目不能更换职业、职业代码、等级、等级导出值或申报类型。同一组合仅报名时间、价格或地点不同，应建立多个批次。

固定“报名信息.xlsx”和“工作经历.xlsx”放在只读 `RENSHE_TEMPLATE_DIR`。管理员上传的承诺书放在独立可写的 `RENSHE_COMMITMENT_TEMPLATE_DIR`；该配置为空时，使用 `UPLOAD_DIR/private/renshe-commitment-templates`。生产Compose将它设为 `/app/uploads/private/renshe-commitment-templates`，由现有uploads持久卷保存，uploads-init按应用UID/GID创建目录并修正所属用户。多实例须共用该持久化存储，备份也应包含该目录。

上传按内容SHA-256命名，先写临时文件、同步并原子发布；不会向固定Excel目录写入。已有位于旧 `RENSHE_TEMPLATE_DIR` 的承诺书继续只读兼容，不必修改项目元数据或移动旧文件；新目录优先读取，所有读取均校验内容哈希。模板不是考生材料，不随报名保留期清理。承诺书当前文件保存在项目配置中，报名提交保留所用文件元数据及实际签署材料，不能借此选择历史导出规则。模板下载均需登录，后台上传需 `content:write`，下载需 `content:read`。

目录不可写、磁盘空间不足或读权限异常时返回503／50410及“承诺书模板存储不可用”，日志包含 `renshe.commitment_template.storage_failed`、操作与errno；错误响应不暴露内部路径或异常栈。上传失败不替换当前项目模板，确认操作失败会显示具体原因并允许重试。

上线先更新Compose环境及uploads-init配置，再重建应用；检查新文件位于uploads持久卷、旧模板仍可下载，并在容器重建后再次下载对比哈希。仅把固定模板挂载改成可写不是本次方案。本地测试可验证应用重建后的读取和持久卷配置，不能代替生产容器重建验收。

批次发布422与上传存储异常分开处理。新批次必须绑定已适配的项目配置，资格规则和材料匹配后才能发布；文案统一为报考组合，不再只指已毕业学历型。当前后台据业务反馈无现存批次，因此本次不执行历史数据迁移或重绑；后续从有效产品新建草稿批次并验证发布。未读取线上异常栈，不能据本地修复断言线上500的最终原因。

## 报名及审核

- 本人实名通过及身份证绑定校验继续保留。新规则不要求学生身份或学生认证；毕业院校、院校类型、学历、专业、毕业日期、证书编号在本次报名保存、审核。
- 民族、政治面貌由实名资料预填，缺失时在报名表补齐并按模板字典校验。姓名、身份证、性别及出生日期仍来自已验证本人资料，缺失或有误须通过实名更正流程处理。
- 文化程度区分中专、技校、职高、高职、大专、大学本科、硕士、博士，并受原批次学历与院校范围限制。从事职业使用模板的“在校学生／应届毕业生／职工／失业人员／其他”，与本次已毕业学历资格分别核验。
- 经本次业务确认，R列固定填写真实参加工作日期，导出格式为2022-9-21，不补零；不接受入学日期或毕业日期替代。S列实际职业年限必填，接受0，不自动用0填补空值。没有参加工作日期的情况联系管理员核实，系统不虚构日期。学历型不增加最低工龄资格门槛。历史学生报名补正页也采集这些实际报送信息，原学历审核与订单不变。
- 新批次身份证正反面复用本人已验证实名资料，报名页上传一寸白底近期证件照（JPG／JPEG，≤500 KB）、毕业证（JPG／JPEG／PDF）、对应学信网学历备案表（PDF）与签署承诺书（JPG／JPEG／PDF）。普通图片≤10 MB、PDF≤20 MB；后端逐次验证扩展名、MIME、文件头和大小，提交再次校验。历史九类材料批次保留原实名照片及材料规则。
- 本期学历型不统一要求社保、工龄、职业资格或职称证书；这些属于其他申报路径，仍待独立适配。毕业证、学历报告及签字按手印承诺书必填，不提供在读替代材料；无法提供既定报告时联系管理员。
- 专业按毕业证原文填写。初审人工核验身份、毕业情况、院校学历、专业相关性、学历报告、一寸白底照片、承诺书七项；后端拒绝未完成核验的通过请求。文件存在与格式合格不等于内容或资格已通过。
- 审核请求带预期报名版本 ID，避免页面停留旧版本后误审核新版本。外审通过继续要求当前版本的成功导出记录。
- 驳回选择具体字段／材料并填写原因、带时区的补正截止时间。截止前允许已支付报名在普通报名关闭后补正；退款冻结、报名关闭、批次取消／归档仍阻断。提交产生独立版本，复用原已支付订单。
- 新学历型不使用直接翻转旧审核结论的“更正审核”入口；使用“打回补正→重新初审”保留核验与期限记录。

## 导出与验收边界

新导出器保留甲方25列及原四个工作表（Sheet1、模板示例、模板说明、申报条件），不增加“毕业学历信息”工作表；毕业学历详情保留在报名版本和后台审核中。导出前核对实际模板标题、下拉字典和职业—申报条件联动；民族、政治面貌及其他模板必填项缺失时拒绝导出。M列使用实际职业状态，U列使用完整字典原文（原文含在读应届字样，但本期资格仍仅接受已取得毕业证人员）；R、S按已确认规则输出，数值0不会变成空值。L、X列分别输出实际工作单位和社保参保单位，不虚构填充。

所有新导出任务使用当前代码维护的25列、平铺目录和固定命名定义，忽略项目及旧报名快照中的历史模板、映射和目录参数；历史JSON字段暂不删除。材料仍取任务创建时关联的独立报名版本，旧报名缺少当前必填信息时须打回补正并重新初审，不能自动填入职业状态、工作日期或年限。

文件树预览与ZIP共同使用 `app/services/renshe_export_definition.py`。身份证及学历附件名称沿用甲方README中的“证件正面、证件背面、学信网电子注册表、学历证明”等；照片文件沿用“二寸免冠照片”的既定报送名称，新批次上传独立一寸白底照片≤500 KB，历史批次按原报名材料要求办理。承诺书为新增业务材料，使用“承诺书”文件名。图片与PDF保留真实扩展名。工作经历.xlsx按甲方README要求保留，目前原样复制原模板，不自动填入考生经历；导出说明明确展示这一用途。

每个任务记录当前代码映射、目录定义及Excel模板内容的指纹；任务开始时核对，并为该任务单独复制两份Excel模板，防止分卷过程中模板被替换。已成功生成任务及其原文件不重写，查询、下载沿用原文件；外审通过仍绑定当前材料版本的成功导出。若未按发布流程清空在途任务，旧指纹任务会明确失败并提示重新创建，不允许切换规则后重试同一个任务。任何已生成成功分卷均保留。

自动化使用隔离SQLite、私有本地对象存储、测试承诺书及真实甲方工作簿，覆盖实际ZIP路径、原始文件格式、固定R／S列、历史文件下载、在途规则升级及补正版本绑定。未操作生产数据库，未执行微信真机上传、真实支付或甲方导入。上线前仍需执行迁移并按甲方实际导入流程验收文件。

## 回滚

按批次关闭新报名入口，保留新配置及数据。已有新格式资料时，迁移降级会拒绝删除新增材料类型约束；使用能识别新旧两类配置的兼容版本回滚。不得删除历史版本或自动判定原在读报名失效，业务方另行确认其补正／退款处理。
