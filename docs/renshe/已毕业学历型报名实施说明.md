# 已毕业学历型报名

适用新配置 `related_major_graduated_degree_v1`：信息安全管理员、四级／中级工、学历型、已取得毕业证。旧项目版本、已发布批次、订单、审核和导出记录不迁移、不覆盖。新发布批次拒绝使用原在读学生规则或其他未适配组合。

旧批次不再新建报名；已有报名仍从“我的报名”继续按原配置办理，不自动失效或退款。后台需先核对历史人员及支付情况，再决定补正或退款处理。

## 启用

1. 暂停创建新导出任务，处理完在途任务后发布兼容的新后端、后台、小程序。执行迁移 `rsh006_current_export`（包含此前的 `rsh005_standard_materials`），只增加任务规则指纹，不重写历史文件或材料。
2. 后台编辑项目，切换至已毕业学历型规则，配置院校及学历范围，保存草稿。项目名称、职业、等级等仍按现有多项目结构管理。
3. 在“导出说明”的独立“承诺书模板”区域上传甲方确认的PDF／DOCX（≤10 MB），可查看当前文件、下载或上传替换。保存后供申请人下载当前模板，用户上传本人签字按手印的JPG／JPEG／PDF扫描件。历史规则项目也能直接设置承诺书，不需要切换资格规则才能看到入口。
4. 导出说明仅展示固定25列表、工作经历表实际生成方式、脱敏目录示例、当前报名模板下载及只读字段说明。不提供模板、列映射、目录、文件名、版本号或R／S规则的编辑控件。项目启用仅检查业务资格、材料要求及承诺书文件，不再要求配置任何导出参数或勾选规则确认。
5. 新建批次，完成报名、支付、初审、导出、外审联调，以及甲方实际导入测试，再发布。不要把已有报名的批次切换到新配置。

模板放在 `RENSHE_TEMPLATE_DIR`，以内容 SHA-256 命名，不能覆盖旧文件；部署多实例时该目录须使用共享、持久化存储，并保留原有“报名信息.xlsx”和“工作经历.xlsx”。模板不是考生材料，不随报名保留期清理。承诺书当前文件保存在项目配置中，内容哈希用于完整性验证；报名提交保留所用承诺书文件元数据及实际签署材料，不能借此选择历史导出规则。模板下载均需登录，后台上传需 `content:write`，下载需 `content:read`。

## 报名及审核

- 本人实名通过及身份证绑定校验继续保留。新规则不要求学生身份或学生认证；毕业院校、院校类型、学历、专业、毕业日期、证书编号在本次报名保存、审核。
- 民族、政治面貌由实名资料预填，缺失时在报名表补齐并按模板字典校验。姓名、身份证、性别及出生日期仍来自已验证本人资料，缺失或有误须通过实名更正流程处理。
- 文化程度区分中专、技校、职高、高职、大专、大学本科、硕士、博士，并受原批次学历与院校范围限制。从事职业使用模板的“在校学生／应届毕业生／职工／失业人员／其他”，与本次已毕业学历资格分别核验。
- 经本次业务确认，R列固定填写真实参加工作日期，导出格式为2022-9-21，不补零；不接受入学日期或毕业日期替代。S列实际职业年限必填，接受0，不自动用0填补空值。没有参加工作日期的情况联系管理员核实，系统不虚构日期。学历型不增加最低工龄资格门槛。历史学生报名补正页也采集这些实际报送信息，原学历审核与订单不变。
- 身份证正反面、二寸免冠照片来自本人已验证实名资料；身份或照片有误须实名更正。社保缴费证明和学信网电子注册表为 PDF，学历证明、职业资格证书、职称证书为 JPG／JPEG，图片 ≤10 MB，PDF ≤20 MB。后端逐次验证扩展名、MIME、文件头、大小，提交时再次读取校验。
- 社保缴费证明、学信网电子注册表、学历证明、职业资格证书、职称证书和签字按手印承诺书全部必填；不提供替代材料路径。无法提供既定材料的申请人联系管理员，本期不自行放宽。
- 专业按毕业证原文填写。初审人工核验身份、毕业情况、院校学历、专业相关性、报送佐证、二寸免冠照片、承诺书七项；后端拒绝未完成核验的通过请求。文件存在与格式合格不等于内容或资格已通过。
- 审核请求带预期报名版本 ID，避免页面停留旧版本后误审核新版本。外审通过继续要求当前版本的成功导出记录。
- 驳回选择具体字段／材料并填写原因、带时区的补正截止时间。截止前允许已支付报名在普通报名关闭后补正；退款冻结、报名关闭、批次取消／归档仍阻断。提交产生独立版本，复用原已支付订单。
- 新学历型不使用直接翻转旧审核结论的“更正审核”入口；使用“打回补正→重新初审”保留核验与期限记录。

## 导出与验收边界

新导出器保留甲方25列及原四个工作表（Sheet1、模板示例、模板说明、申报条件），不增加“毕业学历信息”工作表；毕业学历详情保留在报名版本和后台审核中。导出前核对实际模板标题、下拉字典和职业—申报条件联动；民族、政治面貌及其他模板必填项缺失时拒绝导出。M列使用实际职业状态，U列使用完整字典原文（原文含在读应届字样，但本期资格仍仅接受已取得毕业证人员）；R、S按已确认规则输出，数值0不会变成空值。L、X列分别输出实际工作单位和社保参保单位，不虚构填充。

所有新导出任务使用当前代码维护的25列、平铺目录和固定命名定义，忽略项目及旧报名快照中的历史模板、映射和目录参数；历史JSON字段暂不删除。材料仍取任务创建时关联的独立报名版本，旧报名缺少当前必填信息时须打回补正并重新初审，不能自动填入职业状态、工作日期或年限。

文件树预览与ZIP共同使用 `app/services/renshe_export_definition.py`。身份证及学历附件名称沿用甲方README中的“证件正面、证件背面、学信网电子注册表、学历证明”等；照片文件沿用“二寸免冠照片”的既定报送名称，新标准批次复用已审核实名二寸照片，历史批次按原报名材料要求办理。承诺书为新增业务材料，使用“承诺书”文件名。图片与PDF保留真实扩展名。工作经历.xlsx按甲方README要求保留，目前原样复制原模板，不自动填入考生经历；导出说明明确展示这一用途。

每个任务记录当前代码映射、目录定义及Excel模板内容的指纹；任务开始时核对，并为该任务单独复制两份Excel模板，防止分卷过程中模板被替换。已成功生成任务及其原文件不重写，查询、下载沿用原文件；外审通过仍绑定当前材料版本的成功导出。若未按发布流程清空在途任务，旧指纹任务会明确失败并提示重新创建，不允许切换规则后重试同一个任务。任何已生成成功分卷均保留。

自动化使用隔离SQLite、私有本地对象存储、测试承诺书及真实甲方工作簿，覆盖实际ZIP路径、原始文件格式、固定R／S列、历史文件下载、在途规则升级及补正版本绑定。未操作生产数据库，未执行微信真机上传、真实支付或甲方导入。上线前仍需执行迁移并按甲方实际导入流程验收文件。

## 回滚

按批次关闭新报名入口，保留新配置及数据。已有新格式资料时，迁移降级会拒绝删除新增材料类型约束；使用能识别新旧两类配置的兼容版本回滚。不得删除历史版本或自动判定原在读报名失效，业务方另行确认其补正／退款处理。
