## 1. 交付目标

首版必须在生产等价环境完整跑通以下闭环：

1. 用户在真机小程序中通过微信登录取得业务 Token。
2. 用户上传六类材料，分别提交实名信息和学生信息。
3. 管理员人工审核实名信息和学生信息；两项均为 `verified` 后才能报名。
4. 用户选择 `RS-ZY` 批次，保存草稿并提交不可变报名版本。
5. 系统按批次价格快照建立 60 分钟待支付订单。
6. 小程序通过微信支付 API V3 JSAPI 下单、支付并主动查单；后端通过 V3 回调或查单幂等确认支付。
7. 管理员完成初审；驳回后用户修改认证资料、重新审核并重提，原付款和历史版本保留。
8. 管理员按批次生成一次完整导出任务，产出多个可独立解压的 ZIP，人工送交外部机构。
9. 管理员逐名登记外审结果；系统不对接外部人社审核 API。
10. 用户发起全额退款，超级管理员批准，微信 V3 退款回调或查单确认成功后关闭报名。
11. 批次取消或终结时，系统按规则逐名建立退款申请，并执行批次级敏感数据清理。
12. 生产环境保留期固定 30 天；测试环境允许受控缩短并真实验证 OSS 删除。
13. 管理后台能查询脱敏、只读、不可删除的人社审计日志。

交付成功不是“接口或页面存在”，而是完成一笔真实 0.01 元的“微信登录 → 认证 → 报名 → 微信支付 → 初审 → 导出 → 外审登记 → 用户退款申请 → 超级管理员批准 → 微信退款成功 → 报名关闭”流程，并保留微信交易号、退款号、回调/查单幂等、审核、导出和审计证据。

## 5. 业务状态含义

### 5.1 实名和学生认证状态

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `pending` | 用户已提交，等待管理员人工审核 | 管理员通过或驳回；用户只读 |
| `verified` | 当前资料人工审核通过，永久有效 | 与另一类认证均通过后可建立报名 |
| `rejected` | 当前资料被驳回，原因必须可见 | 用户修改并重新提交，重新进入 `pending` |

实名认证和学生信息必须分别达到 `verified`。任一项不是 `verified` 时，后端必须拒绝建立或重提报名。

### 5.2 批次状态

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `draft` | 未发布草稿，对用户不可见 | 编辑、发布、删除、取消 |
| `published` | 已发布；仅在报名时间窗口内接受新报名 | 编辑允许字段、关闭报名、取消 |
| `registration_closed` | 已人工关闭或报名结束，不再接受新报名 | 终结或取消 |
| `finalized` | 超级管理员完成批次终结，已为符合规则的驳回报名逐名建退款 | 查看退款/导出/清理，随后归档 |
| `cancelled` | 批次取消；未支付订单关闭，已支付未退款订单逐名建退款 | 查看退款和清理，随后归档 |
| `archived` | 业务只读归档 | 只读查询 |

`capacity=0` 表示不限名额。取消和终结均建立批次级清理计划；生产到期时间为状态发生后 30 天，活动退款会暂停并重新计时。

### 5.3 报名状态

| 状态 | 含义 | 用户/管理员动作 |
|---|---|---|
| `draft` | 可编辑草稿，尚未形成待支付订单 | 用户保存、提交 |
| `pending_payment` | 已生成不可变版本和 60 分钟待支付订单 | 用户支付或取消；超时回到草稿 |
| `pending_initial_review` | 微信 V3 已确认支付，等待平台初审 | 管理员初审 |
| `initial_rejected` | 初审驳回，原付款保留 | 用户修改认证资料、重新通过认证后重提 |
| `pending_external_review` | 初审通过，已进入线下外审范围 | 管理员导出并登记外审 |
| `external_rejected` | 外审驳回，原付款保留 | 用户修改、重新认证并从初审重提 |
| `external_approved` | 外审通过，普通退款入口关闭 | 只允许例外退款或只读查询 |
| `closed` | 退款成功或批次规则关闭该次报名 | 旧报名只读；允许按规则再次报名同批次 |

`frozen_at/freeze_reason` 是退款期间的冻结覆盖层，不是新的报名状态。冻结时不允许编辑、重提或重复发起退款。

### 5.4 订单状态

| 状态 | 含义 | 人社用法 |
|---|---|---|
| `pending` | 待支付，60 分钟内有效 | 可预下单、支付、取消或超时关闭 |
| `paid` | 微信 V3 已确认支付 | 人社报名保持该状态，不用订单状态表达审核结果 |
| `completed` | 通用订单的完成态 | 不作为人社审核状态；历史通用业务可使用 |
| `refunded` | 微信 V3 已确认退款成功 | 对应人社报名进入 `closed` |
| `closed` | 未支付订单被取消、超时或批次取消 | 不得再支付 |

### 5.5 退款状态

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `requested` | 用户或系统已逐名建立申请 | 超级管理员批准或驳回 |
| `approved` | 退款决定已批准，准备向微信发起 | 系统使用固定退款单号提交 V3 请求 |
| `processing` | 微信已受理但尚未确认最终成功 | 等待退款回调或后台主动查单 |
| `succeeded` | 微信回调或查单确认 `SUCCESS` | 订单置为 `refunded`、报名关闭、清理计时重算 |
| `rejected` | 超级管理员驳回，必须有理由 | 报名解除冻结并恢复原状态 |
| `failed` | 请求或查询失败，保留脱敏原因 | 超级管理员使用同一退款单号重试 |

微信“请求已受理”不等于退款成功，禁止直接从 `approved` 或接口 HTTP 200 跳到 `succeeded`。

### 5.6 导出和清理状态

| 领域 | 状态 | 含义 |
|---|---|---|
| 导出 | `queued` | 已排队，尚未被 Worker 领取 |
| 导出 | `running` | 正在快照、生成 Excel/ZIP 或上传 OSS，持续记录进度和心跳 |
| 导出 | `succeeded` | 所有独立 ZIP 已生成、校验并可短签下载 |
| 导出 | `failed` | 失败原因已记录，可幂等重试并重新生成完整批次 |
| 清理 | `scheduled` | 已计划，等待 30 天期限到达 |
| 清理 | `running` | 正在删除 OSS 对象和敏感快照 |
| 清理 | `paused` | 有活动退款或其他明确互斥条件，不能删除 |
| 清理 | `succeeded` | 敏感对象已删除，最小财务和审计记录保留 |
| 清理 | `failed` | 删除未完成，记录心跳、重试次数和脱敏错误，可由超级管理员重试 |

## 18. Definition of Done

任一 RSF 任务只有同时满足以下条件才可标记 `DONE`：

1. 代码、迁移、配置或页面满足该行全部验收标准。
2. 正常路径、失败路径、权限边界和至少一个幂等/并发场景有自动化测试。
3. Backend、Admin 和 MP 的契约、类型、字段、状态和文案同步。
4. 涉及外部依赖时必须有真实环境证据；Mock 只能标 `🧪`。
5. 涉及敏感数据时完成越权、脱敏、短签、日志和审计检查。
6. 涉及后台任务时具备心跳、超时、失败原因、重试和进程重启恢复证据。
7. 涉及微信支付时保存脱敏请求标识、微信交易/退款号、验签、回调、查单和幂等记录。
8. 有可复查证据链接或文件：测试日志、截图、OpenAPI、迁移日志、导出黄金样本或 UAT 签字。
