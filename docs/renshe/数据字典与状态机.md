# 人社报名数据字典与状态机

> 版本：2026-08-05 首版冻结稿  
> 产品代码：`RS-ZY`  
> 本文是 Backend 内人社报名字段、枚举和状态转换的唯一实现依据。外部 Todo 中与本文冲突的旧表述，以 2026-08-05 已确认决策和本文为准。

## 1. 全局约定

| 项目 | 约定 |
|---|---|
| 时间 | API 使用带时区 ISO 8601；业务判断使用 `Asia/Shanghai`；数据库使用带时区时间 |
| 金额 | 整数分；不得接收客户端金额；订单保存批次价格快照 |
| 产品 | 仅 `RS-ZY`，职业为“信息安全管理员”，职业编码映射为 `4-04-04-02-网络与信息安全管理员-信息安全管理员-中级工` |
| 等级 | 页面名称“中级工”；标准表等级下拉值固定为“四级” |
| 申报/考试 | `学历型` / `新考` |
| 考生 | 首版仅支持相关专业的在读应届学生；是否符合条件只由管理员人工审核，软件不按学校、专业或日期自动判定 |
| 登录资格 | 必须微信登录；实名信息和学生信息均为 `verified` 后才能建立人社报名 |
| 企业资料 | API、服务和人社流程全部停用；实名 `user_type` 固定为 `student` |
| 文件 | 私有阿里云 OSS；对象键随机且不得含姓名、身份证号、手机号；签名 URL 最长 300 秒 |
| 清理 | 超级管理员按批次完成终结后计时 7 天；活动中的例外退款暂停并重新计算批次清理时间 |

## 2. 认证资料

### 2.1 实名信息（全部必填）

| 字段 | 类型 | 规则 |
|---|---|---|
| `real_name` | string(64) | 真实姓名 |
| `id_card_number` | string(18) | 中国居民身份证，校验码必须有效 |
| `id_card_front_oss` | string(512) | JPG/JPEG，最大 10 MiB |
| `id_card_back_oss` | string(512) | JPG/JPEG，最大 10 MiB |
| `avatar_oss` | string(512) | 二寸免冠照片，JPG/JPEG，最大 10 MiB |
| `ethnicity` | string(16) | 民族 |
| `political_status` | string(16) | 政治面貌 |
| `user_type` | literal | 服务端固定 `student`，客户端不得选择 |

同一时刻，一个有效账号只能占用一个身份证号。比较使用确定性不可逆摘要；账号注销时释放“有效占用”，同时在注销审计表永久保留不可逆摘要，不保留完整号码。

### 2.2 学生信息（全部必填）

| 字段 | 类型 | 规则 |
|---|---|---|
| `education` | enum | `secondary_vocational` / `associate` / `bachelor` / `master` / `doctorate` |
| `school` | string(128) | 院校名称，仅人工审核 |
| `major` | string(128) | 专业名称，仅人工审核 |
| `enrollment_date` | date | 入学日期，仅用于申报和人工审核 |
| `student_card_oss` | string(512) | 学生证 JPG/JPEG，最大 10 MiB |
| `enrollment_pdf_oss` | string(512) | 学信网电子注册表 PDF，最大 20 MiB |
| `degree_cert_oss` | string(512) | 学信网学历证明 JPG/JPEG，最大 10 MiB |

“学信网显示在籍”由审核人员判断为在读。系统不推导毕业年份、不维护专业白名单，也不因日期自动拒绝。

认证状态为 `pending -> verified | rejected`。实名认证通过与学生信息通过缺一不可。认证通过永久有效，但每个报名批次的初审仍须人工复核当批资格。

## 3. 批次

批次字段包括：名称、产品、职业、等级、考试类型、报名开始/截止时间、价格、名额、考试时间、考试地点、报名说明、联系人、联系电话、排序和状态。`capacity=0` 表示不限名额；150 人只是导出容量基线，不是系统总人数上限。

```text
draft -> published -> registration_closed -> finalized -> archived
  |          |                 |
  |          +---------------> cancelled
  +--------------------------> cancelled
```

- `published` 后仍可调整时间、价格、名额、考试信息和说明，且必须审计。
- 调价只影响后续订单；订单金额不得跟随批次变化。
- `cancelled`：关闭未支付订单，并为全部已支付且未退款订单创建系统全额退款任务。
- `finalized`：有待初审/待外审记录时禁止终结；终结时为所有已支付的驳回报名创建系统全额退款任务，并建立批次级 7 天清理计划。

## 4. 报名、订单与冻结

### 4.1 报名状态

```text
draft
  -> pending_payment
  -> pending_initial_review       # 微信支付成功
  -> initial_rejected
  -> pending_initial_review       # 重提，沿用原已付款订单
  -> pending_external_review
  -> external_rejected
  -> pending_initial_review       # 重提后仍从初审开始
  -> external_approved

任一可退款状态 -> closed          # 退款成功
pending_payment -> draft           # 60 分钟超时或用户取消支付
```

- 报名状态与订单状态、退款状态严格分离。
- 首次提交生成不可变版本并创建 60 分钟有效的待支付订单。
- 每次重提生成新的不可变版本；旧版本和旧订单历史不得覆盖。
- 提交时把已通过的实名/学生字段和六类材料复制到版本专属 OSS 对象。
- `pending_payment`、`pending_initial_review`、`pending_external_review` 及活动退款期间锁定实名和学生资料；驳回后允许修改，但修改后的认证资料须再次人工通过才能重提。
- 活动退款申请通过 `frozen_at/freeze_reason` 冻结报名原状态；退款驳回后解冻，退款成功后关闭旧报名。关闭后允许同一用户再次报名同批次。

### 4.2 订单状态

沿用订单状态 `pending -> paid -> refunded`、`pending -> closed`。人社订单必须同时包含 `plan_id` 和 `application_id`。同一报名最多只能有一个 `pending/paid/completed` 有效订单。

## 5. 材料

首版只接受以下六类，全部必传：

| `kind` | 导出文件名 | 类型 | 上限 |
|---|---|---|---:|
| `id_card_front` | `身份证号_证件正面.jpg` | JPG/JPEG | 10 MiB |
| `id_card_back` | `身份证号_证件背面.jpg` | JPG/JPEG | 10 MiB |
| `portrait` | `身份证号_二寸免冠照片.jpg` | JPG/JPEG | 10 MiB |
| `student_card` | `身份证号_学生证.jpg` | JPG/JPEG | 10 MiB |
| `xuexin_registration` | `身份证号_学信网电子注册表.pdf` | PDF | 20 MiB |
| `education_proof` | `身份证号_学历证明.jpg` | JPG/JPEG | 10 MiB |

`social_security`、`vocational_certificate`、`professional_title` 在代码、API、管理端和导出中停用。后端同时检查扩展名、MIME、文件头和大小。

## 6. 审核与更正

- 初审仅接受 `pending_initial_review`；通过进入 `pending_external_review`，驳回进入 `initial_rejected`。
- 外审登记仅接受 `pending_external_review`；通过进入 `external_approved`，驳回进入 `external_rejected`。
- 驳回必须有原因和待修改项。驳回不会退款、关单或释放名额。
- 单次有效决定由一名管理员作出，不设置会签。
- 已登记决定的更正仅超级管理员可执行，必须写独立更正记录和审计日志，不更新或删除原审核记录。

## 7. 退款

```text
requested -> approved -> processing -> succeeded
          -> rejected
processing -> failed -> processing
```

- 用户普通退款仅在外审通过前可申请；例外退款可在任意阶段申请并必须选择原因。
- 批次取消和批次终结退款由系统逐名建立申请，人数不设软件上限。
- 全部为原路全额退款；`amount_cents` 必须等于订单实付金额。
- `due_at` 是申请后的第 3 个工作日（周一至周五，不含节假日配置）。
- 只有超级管理员可以批准、驳回和重试；同一退款单号失败重试时保持不变。
- 微信支付 V3 参数缺失时必须返回明确的外部依赖错误，不得把退款伪造为成功。

## 8. 批次导出

- 每次导出都是全批次重新生成，纳入 `pending_external_review` 和 `external_approved`，排除待审、驳回、已退款/已关闭报名。
- 一个考生的全部内容必须在同一分卷内。每卷不超过 10 GiB；不使用跨文件 ZIP 分卷格式，而是多个可独立解压的 ZIP。
- 每卷包含该卷考生子集的 `报名信息.xlsx`、仅表头的 `工作经历.xlsx` 和材料目录。
- 固定映射：`院校学生`、`应届毕业生`、等级 `四级`、职业编码映射、`学历型`、`新考`；工作单位、职称、社保、职业年限等字段留空。
- 150 人为测试和容量基线；总生成时长不设硬上限，但任务必须有进度、心跳、幂等重试和失败原因。
- 到达批次清理期限或清理已经开始后，禁止新建或重试导出；已排队或正在生成的导出完成前，清理任务不得并发删除材料。

## 9. 批次级清理和审计

- 超级管理员终结批次后建立唯一的活动清理运行，默认 `due_at=finalized_at+7 days`。
- 存在活动例外退款时清理状态为 `paused`；退款处理完成后从完成时间重新计算 7 天。
- 清理删除所有版本附件、生成 Excel/ZIP 和敏感快照；长期保留最小财务记录、状态时间线、操作者和不含完整身份证号的审计摘要。
- 清理任务支持 `scheduled/running/paused/succeeded/failed`，失败可重试并记录心跳、次数和错误。
