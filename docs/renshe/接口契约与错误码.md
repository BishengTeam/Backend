# 人社接口契约与错误码

> 版本：2026-08-07
> 
> 本文描述人社首版的稳定接口边界。运行时 OpenAPI 由 FastAPI 生成；契约检查命令为：
> 
> ```bash
> .venv/bin/python scripts/check_renshe_contract.py
> ```

## 1. 通用约定

- 所有接口返回 `{ "code": 0, "message": "ok", "data": {} }` 结构。
- 时间使用带时区 ISO 8601；业务时区为 `Asia/Shanghai`。
- 金额统一使用整数分；客户端不得提交可信金额。
- 用户端必须使用微信登录后的 Bearer Token。
- 人社报名要求实名信息和学生信息均为 `verified`；企业资料和企业报名接口停用。
- 六类材料全部必传：身份证正面、身份证反面、二寸照片、学生证、学信网电子注册表、学信网学历证明。
- 管理后台材料和导出下载使用不超过 300 秒的私有 OSS 签名 URL。

## 2. 用户端接口

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| POST | `/api/renshe/applications/draft` | 登录用户 | 新建或保存报名草稿 |
| GET | `/api/renshe/applications/{application_id}` | 报名本人 | 查看报名详情和当前状态 |
| POST | `/api/renshe/applications/{application_id}/cancel-payment` | 报名本人 | 取消待支付订单 |
| POST | `/api/renshe/applications/{application_id}/refunds` | 报名本人 | 申请全额退款 |
| POST | `/api/renshe/applications/{application_id}/submit` | 报名本人 | 提交或驳回重提 |
| GET | `/api/renshe/refunds/{refund_id}` | 退款本人 | 查看退款进度 |
| POST | `/api/renshe/verification-materials/{kind}` | 登录用户 | 上传六类认证材料 |
| GET | `/api/renshe/verification-materials/{kind}/signed-url` | 材料本人 | 获取本人材料短链接 |

`submit` 只接受已通过的实名和学生信息；首次提交创建待支付订单，微信支付成功后才进入待初审。驳回不自动退款，重提沿用原报名和原付款记录。

## 4. 统一错误码

| code | HTTP | 含义 | 常见人社场景 |
|---:|---:|---|---|
| 0 | 2xx | 成功 | 请求完成 |
| 40001 | 422 | 参数或材料校验失败 | 文件类型、大小、必填字段错误 |
| 40100 | 401 | 未登录或 Token 无效 | 用户未登录 |
| 40101 | 403 | 无权限 | 普通管理员调用超级管理员接口、越权读取 |
| 40200 | 422 | 业务规则不允许 | 未通过实名/学生审核、批次已截止 |
| 40201 | 409 | 当前状态冲突 | 重复提交、重复退款、状态不允许推进 |
| 40300 | 404 | 资源不存在 | 报名、材料、批次或退款不存在 |
| 40400 | 502 | 外部依赖失败 | 微信支付或 OSS 不可用、V3 凭据缺失 |
| 50000 | 500 | 服务内部错误 | 未预期异常 |

错误响应可在参数校验失败时带 `detail` 字段，字段级错误不得把身份证号、手机号、OSS 完整地址写入日志。

## 5. 冻结和变更规则

1. Backend 修改 Schema 或路由后，先运行契约检查。
2. 生成新的 OpenAPI 后，Admin 和 Platform 必须更新对应类型和调用流程。
3. 删除、重命名字段或状态属于破坏性变更，必须先更新数据字典、错误码和三端评审记录。
4. 不允许通过旧的通用认证报名接口实现人社报名。
