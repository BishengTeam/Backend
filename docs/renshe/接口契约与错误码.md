# 人社接口契约与错误码

> 版本：2026-08-10
> 
> 本文描述人社首版的稳定接口边界。运行时 OpenAPI 由 FastAPI 生成；契约检查命令为：
> 
> ```bash
> .venv/bin/python scripts/check_renshe_contract.py
> ```

## 1. 通用约定

- 业务接口返回 `{ "code": 0, "message": "ok", "data": {} }` 结构。微信支付通知例外，直接返回 V3 ACK。
- 时间使用带时区 ISO 8601；业务时区为 `Asia/Shanghai`。
- 金额统一使用整数分；客户端不得提交可信金额。
- 用户端必须使用微信登录后的 Bearer Token。
- 人社报名要求实名信息和学生信息均为 `verified`；企业资料和企业报名接口停用。
- 六类材料全部必传：身份证正面、身份证反面、二寸照片、学生证、学信网电子注册表、学信网学历证明。
- 管理后台材料和导出下载使用不超过 300 秒的私有 OSS 签名 URL。

## 2. 用户端接口

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/api/renshe/applications` | 登录用户 | 分页查询本人全部报名，作为换机/重装后的恢复入口 |
| POST | `/api/renshe/applications/draft` | 登录用户 | 新建或保存报名草稿 |
| GET | `/api/renshe/applications/{application_id}` | 报名本人 | 查看报名详情和当前状态 |
| POST | `/api/renshe/applications/{application_id}/cancel-payment` | 报名本人 | 取消待支付订单 |
| POST | `/api/renshe/applications/{application_id}/refunds` | 报名本人 | 申请全额退款 |
| POST | `/api/renshe/applications/{application_id}/submit` | 报名本人 | 提交或驳回重提 |
| GET | `/api/renshe/refunds/{refund_id}` | 退款本人 | 查看退款进度 |
| POST | `/api/renshe/verification-materials/{kind}` | 登录用户 | 上传六类认证材料 |
| GET | `/api/renshe/verification-materials/{kind}/signed-url` | 材料本人 | 获取本人材料短链接 |
| POST | `/api/payment/prepay` | 订单本人 | 微信支付 V3 JSAPI 预下单，金额只取订单价格快照 |
| POST | `/api/payment/orders/{order_id}/sync` | 订单本人 | 主动向微信 V3 查单并恢复支付结果，按用户 10 次/分钟限流 |

`submit` 只接受已通过的实名和学生信息；首次提交创建待支付订单，微信支付成功后才进入待初审。驳回不自动退款，重提沿用原报名和原付款记录。

`GET /api/renshe/applications` 支持 `plan_id`、`status`、`page`、`page_size`，数据库查询始终附加当前 Token 对应的 `user_id`，不接受客户端传入用户 ID。结果按 `updated_at DESC, id DESC` 排序，包含报名关键时间、批次摘要、最新订单（含价格快照和过期时间）及最新退款；草稿、待支付和 `closed` 历史均不隐藏。报名版本、驳回原因等完整信息继续通过详情接口读取。

## 3. 微信支付 V3 通知与查单

- `POST /api/payment/callback` 不使用 Bearer Token；必须校验 `Wechatpay-Timestamp`、`Wechatpay-Nonce`、`Wechatpay-Signature`、`Wechatpay-Serial`，再用 32 字节 API V3 Key 解密 AES-GCM `resource`。
- `POST /api/payment/refund-callback` 同样不使用 Bearer Token，且只接受 `REFUND.SUCCESS`、`REFUND.ABNORMAL`、`REFUND.CLOSED` 三类 V3 退款通知；事件类型必须与解密后的退款状态一致。
- 通知、本人主动查单和后台待支付对账 Worker 共用同一个订单行锁事务；校验 AppID、商户号、金额、币种、`attach=order:{id}`、付款人 openid 和交易号唯一性。
- 通知成功直接返回 `{ "code": "SUCCESS", "message": "成功" }`；验签、解密或业务校验失败返回 HTTP 400 和 `{ "code": "FAIL", "message": "失败" }`；临时内部故障返回同一 FAIL 结构及 HTTP 500，供微信重试。
- 重复通知、主动查单与 Worker 竞争不会重复确认名额或履约。订单已退款时收到旧成功结果不得回退状态；订单已关闭或微信成功时间晚于订单过期时间时，不重新履约，并记录待退款复核异常。
- 全站支付通信仅使用 `/v3/pay/transactions/*` 和 `/v3/refund/domestic/refunds*`；不保留旧协议运行时配置。

## 4. 管理端接口

| 方法 | 路径 | 最低权限 | 用途 |
|---|---|---|---|
| GET | `/admin/certifications/{code}/plans/{plan_id}/impact?action=cancel` | `user:write` | 只读预览取消批次影响 |
| GET | `/admin/certifications/{code}/plans/{plan_id}/impact?action=finalize` | 超级管理员 | 只读预览终结批次影响与阻断项 |
| GET | `/admin/renshe/applications` | `user:list` | 报名列表和筛选 |
| GET | `/admin/renshe/applications/{application_id}` | `user:list` | 报名详情与版本历史 |
| POST | `/admin/renshe/applications/{application_id}/initial-review` | `user:write` | 人社初审 |
| POST | `/admin/renshe/applications/{application_id}/external-review` | `user:write` | 登记外部复审 |
| POST | `/admin/renshe/reviews/{review_id}/corrections` | 超级管理员 | 更正审核结果 |
| GET | `/admin/renshe/users/{user_id}/verification-materials/{kind}/signed-url` | `user:list` | 预览实名/学生审核材料 |
| GET | `/admin/renshe/materials/{material_id}/signed-url` | `user:list` | 预览报名版本材料 |
| POST | `/admin/renshe/plans/{plan_id}/exports` | `user:write` | 创建全批次导出任务 |
| GET | `/admin/renshe/plans/{plan_id}/exports` | `user:list` | 查看导出历史 |
| GET | `/admin/renshe/exports/{job_id}` | `user:list` | 查看导出进度和分卷 |
| POST | `/admin/renshe/exports/{job_id}/retry` | `user:write` | 重试失败导出 |
| GET | `/admin/renshe/export-volumes/{volume_id}/signed-url` | `user:list` | 下载独立 ZIP 分卷 |
| GET | `/admin/renshe/refunds` | `order:list` | 退款工作台 |
| POST | `/admin/renshe/refunds/{refund_id}/decision` | 超级管理员 | 批准、驳回或重试退款 |
| GET | `/admin/renshe/audit-logs` | `user:list` | 按批次、报名、管理员、动作、结果和时间分页查询脱敏只读审计 |
| GET | `/admin/renshe/plans/{plan_id}/cleanup-runs` | `user:list` | 查看批次清理任务 |
| POST | `/admin/renshe/cleanup-runs/{run_id}/retry` | 超级管理员 | 重试清理任务 |

影响预览响应包含 `affected_application_count`、`pending_order_close_count`、`refund_candidate_count`、`refund_amount_cents`、`blocking_application_count`、`blocking_status_counts`、`cleanup_due_at`、`can_execute` 和机器可读 `blockers`。已有活动或成功退款的订单不会重复计入退款候选。该接口不加行锁、不写审计、不创建退款或清理任务；取消/终结执行接口必须在独立事务中重新检查权限、批次状态、报名、订单和退款。

## 5. 统一错误码

| code | HTTP | 含义 | 常见人社场景 |
|---:|---:|---|---|
| 0 | 2xx | 成功 | 请求完成 |
| 40001 | 422 | 参数或材料校验失败 | 文件类型、大小、必填字段错误 |
| 40100 | 401 | 未登录或 Token 无效 | 用户未登录 |
| 40101 | 403 | 无权限 | 普通管理员调用超级管理员接口、越权读取 |
| 40200 | 422 | 业务规则不允许 | 未通过实名/学生审核、批次已截止 |
| 40201 | 409 | 当前状态冲突 | 重复提交、重复退款、状态不允许推进 |
| 40300 | 404 | 资源不存在 | 报名、材料、批次或退款不存在 |
| 40400 | 502 | 外部依赖失败 | 微信支付或 OSS 不可用、V3 凭据缺失 |
| 50000 | 500 | 服务内部错误 | 未预期异常 |

错误响应可在参数校验失败时带 `detail` 字段，字段级错误不得把身份证号、手机号、OSS 完整地址写入日志。

## 6. 冻结和变更规则

1. Backend 修改 Schema 或路由后，先运行契约检查。
2. 生成新的 OpenAPI 后，Admin 和 Platform 必须更新对应类型和调用流程。
3. 删除、重命名字段或状态属于破坏性变更，必须先更新数据字典、错误码和三端评审记录。
4. 不允许通过旧的通用认证报名接口实现人社报名。
