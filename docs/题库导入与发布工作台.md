# 题库导入与发布工作台

本次修改在现有题库、模块、知识点、题目修订和导入 Worker 上完成。Admin 与 Backend 需要配套更新；小程序接口契约不变。本次只提交代码，没有部署或调整业务数据。

## 管理员流程

1. 在题库工作台选择题库，进入题目、分类管理或导入记录。
2. 点击上传题库，目标题库自动带入。使用新版 XLSX 模板；只读取第一张工作表。
3. 查看导入检查：内容错误直接展开；分类安排显示复用、新建和默认归属；可查看题目预览、下载错误报告。
4. 所有有效文件均须确认一次，之后由 Worker 原子创建分类和草稿题目。内容检查通过数量与实际创建数量分别显示。
5. 用系统补齐归属或归属不可用筛选题目，勾选后批量调整归属。目标必须是同题库的启用普通知识点；必要时可在窗口内新建模块或知识点。
6. 人工审核后点击检查并发布。明确选择题目修订、发布题库、开放用户入口，三个选择互相独立。未选草稿继续保留。
7. 发布任务逐阶段显示实际结果。重新打开检查窗口可查询最近 20 个任务，失败后继续未完成阶段。

## 分类规则

| 模块 | 知识点 | 归属 |
| --- | --- | --- |
| 网络基础 | TCP | 网络基础 → TCP |
| 网络基础 | 留空 | 网络基础 → 默认知识点（首次为综合练习） |
| 留空 | TCP | 默认模块（首次为基础题目）→ TCP |
| 留空 | 留空 | 默认模块 → 默认知识点 |

默认节点使用普通身份 `system_kind=none`，具备完整的发布、练习、组卷和统计能力。`is_import_default` 是稳定标识，改名后继续复用；有效默认节点包含停用状态，每题库最多一个默认模块，每模块最多一个默认知识点。

同名启用普通节点可在确认后关联默认标识；同名停用、删除保留名称或系统节点不会静默恢复、覆盖。明确指定的停用分类可接收草稿，发布前必须处理。

旧两级路径继续支持。一级按模块处理，缺少的知识点使用默认知识点；保留空槽位置，`/TCP` 表示默认模块下的 TCP；超过两级报错。新独立字段与旧路径冲突时拒绝猜测归属。CSV 的 `category_path` 可以留空或为 `[]`；结构化 JSON 可以省略路径，或提供 `module_name`、`knowledge_point_name`。旧三层分类任务不适用新的 V2 默认规则。

同一任务的重复请求、Worker 重试不会重复写入；不同新任务仍沿用逐行导入规则，不额外引入跨任务题干去重。重复题干的内容、答案和分值不会被自动合并。

## 一致性与权限

- 导入预检对节点 ID、名称、状态、版本及默认安排签名。确认后的执行重新计算；变化时回到待确认，保持零写入。
- 导入按题库加锁，默认节点有数据库唯一约束；分类及整批草稿在同一事务创建。
- 系统补齐筛选读取题目来源标识 `import_default_ownership`；人工移动后清除该来源标识。默认节点自身标识保留。
- 批量移动保留逻辑题目和修订，不修改内容或历史答题快照；逐项版本校验、审计并重新检查迁移问题。
- 上传、确认、编辑和发布继续使用既有权限。确认导入仍要求导入及编辑权限；发布任务创建、继续和各执行阶段都检查对应发布或管理权限。
- 发布请求保存精确的题目 ID、修订 ID、乐观锁版本。修改后的新修订不能被旧任务顺带发布。
- 每次 Worker 最多原子提交 100 道题目，或一个题库/入口阶段。业务修改与阶段游标同事务提交，失败保留已完成结果。全部选定阶段完成才标记成功。
- 入口仍检查激活码、积分兑换或课程权益；开放入口不会授予个人权益。

## 后端入口

- `GET /admin/quiz/libraries/{id}/publication-preflight`：只读统计、阻断、可修复问题、建议及候选修订；不修复、不发布数据。
- `POST /admin/quiz/ownership-moves`：最多 100 题，同题库有效目标，逐项校验版本。
- `GET/POST /admin/quiz/libraries/{id}/publication-operations`：查询/创建阶段任务。
- `GET /admin/quiz/publication-operations/{id}`、`POST .../{id}/resume`：阶段结果/继续。
- `GET /admin/quiz/imports/{id}/preview`：每页 20 道原文件题目预览。
- 导入记录支持 `library_id`，保留独立跨题库查询入口。

## 迁移与上线前核对

迁移 `quiz019` 新增默认标识、来源标识、源文件名与发布任务表。没有批量回填分类、自动启用题库或改写历史题目。按既有部署流程执行 `alembic upgrade head`，更新 Admin，并确认现有题库 Worker 运行且加载 `quiz-publication` 处理器。

上线前对目标库逐个调用只读预检，核对系统待整理、归属不可用、迁移阻断、已发布但入口关闭及待确认导入；由管理员按结果明确整理。已解决的结构问题由原迁移复核机制关闭，其他问题保留。

优先用测试题库验收四种分类、旧模板、错误行、并发确认、分类改名/停用、任务重试及权限。不要因发布检查提示就自动移动或发布存量题目。

回滚时先停止新入口与任务创建，处理在途任务，保留新增列和已有默认节点、任务、导入内容；已有新格式数据时不运行破坏性降级。已发布题目继续通过原有停用流程处理。
