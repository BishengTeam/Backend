## 2. 前后端数据流现状

```
点击用户 → 查看详情
  │
  ├── GET /admin/users/{user_id}          → 仅返回 { id, openid, phone, is_active, created_at }
  ├── GET /admin/users/{user_id}/orders   → 订单记录
  └── GET /admin/users/{user_id}/conversations → AI 对话
```

**问题：** `GET /admin/users/{user_id}` 只返回 5 个基础字段，不包含：

- 个人资料（性别、学历、学校、专业、单位、邮箱、头像等） — 这些字段在 `UserProfileDetail` 中存在
- 实名认证信息（真实姓名、身份证号、证件照、审核状态等） — 这些字段在 `UserIdentityResponse` 中存在

---

## 3. 缺失的管理后台接口

| 缺失接口 | 用途 | 对应已有接口 |
|---------|------|------------|
| `GET /admin/users/{user_id}/profile` | 查看用户完整个人资料 | `GET /api/user/profile`（仅返回当前登录用户自己的数据） |
| `GET /admin/users/{user_id}/identity` | 查看用户实名认证详情 | `GET /api/user/identity`（仅返回当前登录用户自己的数据） |

> `/api/user/profile` 和 `/api/user/identity` 是从小程序 Token 中提取 `user_id`，管理员无法通过这两个接口查看**其他用户**的资料。

## 4. 前端已就绪

前端已为上述两个接口预留了完整的 UI 和数据模型：

- **类型定义** `src/types/user.ts`：
  - `UserDetail` 已包含 `identity?: UserIdentityInfo`
  - `UserIdentityInfo` 包含 `user_type` / `real_name` / `id_card_number` / 证件照 OSS key / `status` / `verified_at` 等字段

- **用户详情抽屉** `src/pages/users/components/UserDetailDrawer.tsx`：
  - 实名认证信息展示区（认证类型、姓名、脱敏身份证号、审核状态 Tag）
  - 当 `identity.status === 'pending'` 时显示「通过」「驳回」按钮
  - 驳回时弹出 Modal 输入驳回原因（256 字以内）
  - 调用 `PUT /admin/users/{user_id}/identity/review` 提交审核结果

- **服务层** `src/services/users.ts`：
  - `reviewIdentity(id, { status, comment? })` — 审核接口 ✅

**一旦后端新增上述 2 个 GET 端点，前端只需在 `handleRowClick` 中增加两次并行请求即可完成对接，无需改动 UI 组件。**

## 5. 建议后端新增端点

```
GET  /admin/users/{user_id}/profile
     → 返回 UserProfileDetail（或内嵌在 GET /admin/users/{user_id} 响应中）

GET  /admin/users/{user_id}/identity
     → 返回 UserIdentityResponse（或内嵌在 GET /admin/users/{user_id} 响应中）
```

或者，将 profile 和 identity 数据直接合入 `GET /admin/users/{user_id}` 的响应体中，前端无需额外请求。
