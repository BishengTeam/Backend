# 计划（批次）设计

## 核心定义

```
计划(Plan) = 认证产品 × 报名时间段 × 状态管理
```

计划是认证产品下的一个**报名批次**。一个认证产品可以有多个计划（如 2026 年上半年、2026 年下半年），每个计划有独立的报名时间窗口和名额。

### 示例

```
认证产品:   人社-网络与信息安全管理员 (product_type: RENSHE-XXAQ)
  计划 #1:  2026 年第二批，8月8日考试，7月13日截止报名
  计划 #2:  2026 年第三批，12月考试，11月截止报名
```

### 与其他域的关系

```
certification (认证产品)
  └── plan (计划/批次)
        └── order (报名订单)
              └── asset (材料)
              └── payment (支付)
              └── approve (审核)
```

## 数据抽象

### Plan 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `product_type` | string(64) | 所属认证产品，对应 `certification.code` |
| `name` | string(128) | 批次名称，如「2026年第二批」 |
| `apply_start` | datetime | 报名开始时间 |
| `apply_end` | datetime | 报名截止时间 |
| `exam_date` | datetime | 考试日期（可选） |
| `capacity` | int | 总名额（可选，0 表示不限制） |
| `status` | string(16) | draft → published → archived |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### 状态流转

```
draft (草稿) → published (已发布) → archived (已归档)
                    ↓
              cancelled (已取消)
```

- **draft**: 管理员创建，前端不可见
- **published**: 已发布，用户可报名，到达报名截止时间后自动或手动关闭
- **archived**: 考试结束，批次归档，仅可查看
- **cancelled**: 发布后取消（异常情况）

## Order 表改动

| 字段 | 操作 | 说明 |
|------|------|------|
| `plan_id` | 新增 | 可空 FK → `plan.id`；兼容历史订单，新专用下单接口强制传入 |

创建订单时，通过 `plan_id` 确定所属计划，直接从 plan 获取 `product_type`、报名时间等信息。订单仍保存 `product_type` 和成交价格作为历史快照，不再信任客户端传入的认证代码。

批次容量通过订单状态动态统计：`pending`、`paid`、`completed` 占用名额，`closed`、`refunded` 释放名额，`capacity = 0` 表示不限名额。创建订单时锁定 plan 行并在同一事务内检查容量，避免并发超额报名。

同一用户在同一批次只允许存在一个有效订单（`pending`、`paid`、`completed`）。订单关闭或退款后可重新报名；服务层在批次锁内提前校验，数据库使用部分唯一索引兜底。

## API 设计

### 管理端

| 接口 | 说明 |
|------|------|
| `GET /admin/certifications/{code}/plans` | 某认证下的计划列表 |
| `POST /admin/certifications/{code}/plans` | 创建计划 |
| `PUT /admin/certifications/{code}/plans/{plan_id}` | 编辑计划 |
| `PUT /admin/certifications/{code}/plans/{plan_id}/publish` | 发布计划 |
| `PUT /admin/certifications/{code}/plans/{plan_id}/archive` | 归档计划 |
| `DELETE /admin/certifications/{code}/plans/{plan_id}` | 删除草稿计划 |
| `GET /admin/certifications/{code}/plans/{plan_id}/orders` | 批次订单列表，支持 `status`、`phone` 和分页 |
| `GET /admin/certifications/{code}/plans/{plan_id}/approvals` | 批次订单审核记录，支持 `action` 和分页 |

### 用户端

| 接口 | 说明 |
|------|------|
| `GET /api/plans?product_type=H3C-RE` | 可报名的计划列表（仅 published） |
| `GET /api/plans/{id}` | 计划详情（含剩余名额） |
| `POST /api/orders/h3c {plan_id:1, ...}` | 在指定计划下报名，认证代码由批次推导 |

## 与现有系统的融合

现有订单通过 `extra_data` 自由存报名字段。引入 plan 后：

1. 新建 `plan` 表，迁移脚本填充历史数据（默认一个历史计划，把现有订单关联进去）
2. 各认证（H3C/NISP/深信服/人社）共用 `plan` 表，通过 `product_type` 区分
3. 订单创建时校验 `plan.status == published` 且 `apply_start <= now <= apply_end`
4. 报名截止后，已建订单照常走支付-审核流程，但不再接受新订单

### 当前接入状态（2026-07-14）

- `order.plan_id` 模型和迁移已增加，历史订单允许为空
- 通用报名资格、时间窗口和并发容量检查已实现
- H3C 专用下单接口已接入 `plan_id`
- 通用批次订单和审核记录查询接口已实现
- 深信服、NISP、人社专用下单接口待后续接入

## 对比我们的现状

| 功能 | 参考后台（人社） | 我们（目标） | 我们（现状） |
|------|:---:|:---:|:---:|
| **计划/批次表** | `plan` | `plan` | 无 |
| **批次状态管理** | draft → published → archived | 相同 | 无 |
| **认证产品与批次关系** | 1:N（cert → plans） | 相同 | 1:1（cert 直接到 order） |
| **报名时间窗口** | `apply_start` / `apply_end` | 相同 | 无（订单无时间校验） |
| **考试日期** | `exam_date`（在 plan 上） | 相同 | H3C 用 `extra_data.exam_datetime` |
| **名额限制** | `capacity` | 相同 | 无（需接入 inventory 但未实现） |
| **报名截止后处理** | 不接受新订单，已有订单正常走完 | 相同 | 无机制 |
| **后台创建批次** | `POST /api/plan/save` | `POST /admin/plans` | 无 |
| **后台发布批次** | `POST /api/plan/publish/{id}` | `PUT /admin/plans/{id}/publish` | 无 |
| **后台关闭批次** | `POST /api/plan/archive/{id}` | `PUT /admin/plans/{id}/archive` | 无 |
| **用户选批次报名** | `POST /api/apply/save {planId}` | `POST /api/orders/h3c {plan_id}` | 不选批次，直接下单 |
| **用户看可选批次** | 隐含在报名页 | `GET /api/plans?product_type=H3C-RE` | 无 |
| **按批次查看订单** | `GET /api/apply/list/{planId}` | `GET /admin/plans/{id}/orders` | 只能按 product_type 筛选 |
| **按批次查看审核** | `GET /api/approve/list/{planId}` | `GET /admin/plans/{id}/approvals` | 只能按 target_type 筛选 |
| **报名材料管理** | `asset` 独立表，支持审核 | 沿用 `order.attachments` | `order.attachments`（JSON 数组） |
| **电子签名** | 审核人有签字字段 | 可后续加 | 无 |
| **PDF 导出** | `GET /api/apply/pdf/{id}` | 可后续加 | 无 |

### 差距总结

| 级别 | 项 | 说明 |
|:---:|------|------|
| 🔴 核心缺 | 批次概念 | 所有认证报名都需要先建批次才能报名，当前跳过了这个层 |
| 🔴 核心缺 | 时间窗口校验 | 报名无开始/截止时间约束 |
| 🟡 重要缺 | 容量上限 | 无报名人数限制 |
| 🟡 重要缺 | 按批次聚合 | 订单列表、审核列表无法按批次维度查看 |
| 🟢 可后续 | 材料审核、签名、PDF | 增强功能，非阻塞 |
