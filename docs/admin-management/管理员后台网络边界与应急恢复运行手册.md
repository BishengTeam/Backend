# 管理员后台网络边界与应急恢复运行手册

> 适用范围：生产 `docker-compose.deploy.yml` 部署的 Admin 页面、`/admin/*` 接口与唯一超级管理员应急恢复。
>
> 边界：不在业务数据库实现 IP 白名单，不开发动态验证码。网络准入由 Tailscale、反向代理和主机/云防火墙共同完成。

## 1. 强制网络边界

生产 Compose 只允许以下宿主机端口映射：

- Backend：`127.0.0.1:${BACKEND_PORT:-8000}:8000`
- Admin：`127.0.0.1:${ADMIN_PORT:-8080}:80`

不得改为裸端口、`0.0.0.0` 或 `[::]` 绑定。`tests/unit/test_admin_network_boundary.py` 对这项要求做静态门禁。环回绑定只能阻止容器端口被直接访问，不能代替反向代理的路由隔离。

推荐路由是：

```text
受控终端 -> Tailscale/零信任准入 -> 内网 HTTPS 反向代理
                                           |-> 127.0.0.1:8080 Admin
                                           `-> 127.0.0.1:8000 /admin/*

公网终端 -> 公网 API 反向代理 -> 显式拒绝 /admin 和 /admin/*
                                      `-> 127.0.0.1:8000 允许的公开 API
```

实施要求：

1. Admin 域名只在 tailnet/受控接入层发布，或在反向代理上仅监听 Tailscale 网卡地址。
2. 公网 API 虚拟主机必须在通用 Backend 转发规则之前，对 `/admin` 和 `/admin/*` 设置精确的 `403` 或 `404`。
3. 主机或云防火墙不得放行 Backend/Admin 容器映射端口；只放行业务所需 HTTPS 和受控运维入口。
4. 反向代理必须保留审计所需的请求 ID 和经过可信代理规范化的客户端 IP，不得盲目信任公网客户端伪造的转发头。

## 2. 网络边界 UAT

每次生产发布后从三个视角验证，不得只在服务器本机执行 `curl`。

### 2.1 服务器本机

```bash
sudo docker compose --env-file .env -f docker-compose.deploy.yml config
sudo ss -lntp
```

验收：Backend/Admin 映射端口只出现在 `127.0.0.1`，不出现在 `0.0.0.0` 或 `[::]`。同时检查 `nft list ruleset`、`ufw status verbose` 或云防火墙的实际生效规则。

### 2.2 非受控公网终端

```bash
curl --connect-timeout 5 -i https://admin.example.com/
curl --connect-timeout 5 -i https://api.example.com/admin/auth/me
```

验收：Admin 页面不可达，或由边界层返回 `403/404`；公网 API 不得把 `/admin/*` 请求转发到 Backend。不能以 Backend 返回的 `401` 作为网络隔离通过的证据。

### 2.3 受控 Tailscale/内网终端

```bash
curl --connect-timeout 5 -I https://admin.internal.example.com/
curl --connect-timeout 5 -i https://admin.internal.example.com/admin/auth/me
```

验收：Admin 页面可达；未登录的 `me` 请求由 Backend 返回预期的未认证响应。再使用超级管理员和题库管理员各完成一次权限 UAT。

验收记录应包含发布 commit/镜像摘要、时间、操作人、测试来源网络、返回状态、请求 ID 和防火墙/代理规则摘要；不记录 Cookie、令牌或密码。

## 3. 唯一超级管理员应急恢复

仅在唯一超级管理员无法登录、正常自助解锁/改密无法使用时执行。命令不接受目标用户名或密码参数，不创建第二个超级管理员，也不支持恢复普通管理员。

### 3.1 执行前

1. 由两名授权人员确认工单和当前故障，记录镜像版本与数据库备份引用。
2. 确认已执行管理员安全迁移，数据库中必须恰好存在一个 `super_admin`。
3. 从服务器受控交互终端执行；禁止通过 CI、定时任务、管道或非交互 shell 调用。

### 3.2 执行命令

```bash
sudo docker compose --env-file .env -f docker-compose.deploy.yml \
  exec -e ENABLE_SUPER_ADMIN_RECOVERY=1 app \
  python scripts/recover_super_admin.py
```

命令会显示唯一目标账号，要求输入完整的 `RECOVER <username>` 确认短语，再两次无回显读取新的临时密码。密码必须满足冻结规则且不能与最近 5 次重复。

成功后会在同一事务中：

- 重新启用唯一超级管理员，清除失败次数和临时锁定。
- 安全哈希并更换密码，追加密码历史，仅保留最近 5 次。
- 设置 `must_change_password=true`，递增 `auth_version` 使所有旧会话失效。
- 追加 `admin_account.emergency_recovery` 安全审计，不记录明文密码、哈希或令牌。

任一数据库操作失败都会回滚全部变更。

### 3.3 恢复后验证

1. 使用新临时密码登录，必须进入受限会话并被强制修改密码。
2. 修改后重新登录，确认管理员账号页和题库业务可用。
3. 验证恢复前的所有浏览器会话在下一次请求时失效。
4. 在安全审计页按动作 `admin_account.emergency_recovery` 查询，确认目标账号、时间、成功结果和来源标记完整。
5. 将验证结果、工单号、备份引用、操作人和复核人记入运维记录，不记录临时密码。
