## 1. 文档定位

本文是管理员账号、预设角色、后台认证和管理员安全审计的唯一有效开发清单。后续实施前必须先更新本文状态，实施中不得以现有零散接口或静态权限代码替代本文验收标准。

本轮要解决的核心问题不是简单补一个管理员列表页面，而是停止多人长期共享唯一超级管理员账号，并建立可审计、可停用、可立即收回权限的后台账号体系。

## 2. 实施前真实基线（已被本轮实现替代）

### 2.1 Backend 已有能力

- `AdminUser` 当前仅支持 `super_admin` 和 `admin` 两个角色。
- `ROLE_PERMISSIONS` 当前为代码内静态映射；`super_admin` 使用 `*`，`admin` 拥有一组较宽的跨模块权限。
- `/admin/settings/admins` 已有管理员列表、新建普通管理员、启停普通管理员和重置密码等基础接口。
- 以上接口统一要求 `require_super_admin`，但缺少首次改密、密码历史、登录锁定、账号级会话失效和独立安全审计。
- 管理员账号事件当前写入人社领域的 `RensheAuditLog`，领域归属错误，无法作为完整的管理员安全审计模型。
- 管理员 JWT 当前固定有效 120 分钟；退出登录只拉黑当前令牌，尚不能可靠地一次失效某账号的全部会话。
- 每次管理员请求会重新读取 `AdminUser`，因此账号停用能够阻止后续业务请求，但尚未形成统一的账号状态机和前端下线体验。

### 2.2 Admin 当前缺口

- 没有“系统管理”菜单、管理员账号页面或管理员安全审计页面。
- 没有首次登录强制修改密码页面。
- 右上角账号菜单只有退出登录，没有修改密码。
- 登录后固定进入数据看板，不能按角色进入第一个有权限的页面。
- 菜单和路由支持权限过滤，但当前普通管理员仍使用过宽的静态权限集合。
- `/admin/auth/me` 失败时存在保留本地令牌并继续使用旧权限状态的降级逻辑，不能满足权限变更后的即时收回要求。

### 2.3 基线结论

现有代码只能视为可复用骨架，不能标记为管理员管理模块已完成。正式实施仍需重新冻结模型、迁移、契约、认证状态机、页面和端到端验收。

## 3. 已冻结业务规则

### 3.1 固定角色

第一期只启用两个系统预设角色：

| 角色代码 | 中文名称 | 边界 |
|---|---|---|
| `super_admin` | 超级管理员 | 唯一系统级管理员；拥有全部后台能力，并管理管理员账号 |
| `quiz_admin` | 题库管理员 | 只访问题库模块；拥有题库模块完整生命周期操作能力 |

角色规则：

- 不提供自定义角色功能。
- 不提供权限勾选页面。
- 不允许给单个管理员追加或移除权限。
- 不建立可编辑的角色表、权限表或角色权限关联表。
- `admin_user.role` 只存系统发布的固定角色代码。
- 角色到内部权限代码的映射由 Backend 代码版本管理。
- 新增岗位角色必须同时发布 Backend 权限映射、数据库约束/迁移、Admin 菜单与路由、契约和自动化测试。

### 3.2 题库管理员边界

`quiz_admin` 拥有题库模块完整操作能力，包括：

- 题库创建、编辑、课程绑定和访问配置。
- 模块、知识点、题目及修订的创建、编辑和生命周期管理。
- 导入任务创建、确认、重试、错误报告和文件下载。
- 查看并接管其他题库管理员创建的导入任务；不按操作者做数据隔离。
- 发布、停用、归档、恢复，以及满足既有业务约束后的删除。
- 聚合统计、题库业务审计和任务监控。

`quiz_admin` 不得：

- 访问管理员账号或管理员安全审计。
- 访问用户、订单、人社、财务及其他非题库业务页面。
- 通过直达 URL 或直接调用 API 绕过角色限制。

题库内不做题库、课程、模块或知识点级数据范围授权。同一角色的管理员共享全部题库数据和任务。风险由既有状态约束、二次确认、告警和题库业务审计控制。

### 3.3 唯一超级管理员

- 系统最多存在一个 `super_admin`。
- 后台不能创建第二个超级管理员。
- 管理员列表中的超级管理员只读展示。
- 不能从管理员列表停用、改角色或重置超级管理员密码。
- 超级管理员可以通过右上角账号菜单修改自己的密码，但必须先验证当前密码。
- 超级管理员凭据丢失或锁定无法等待时，只能通过受控服务器运维命令恢复。
- 日常题库运营必须使用 `quiz_admin`，不应继续使用超级管理员账号。

### 3.4 管理员身份字段

- 登录用户名创建后不可修改。
- 用户名创建时去除首尾空格并转为小写。
- 用户名长度为 4～32 位，必须以小写字母开头，只允许小写字母、数字、点、下划线和短横线。
- 数据库必须按大小写不敏感方式保证用户名唯一。
- 管理员姓名/显示名必填，用于顶部账号区域、列表和审计日志。
- 第一期不收集管理员手机号或邮箱。
- 管理员账号永不物理删除，只能启用或停用。

### 3.5 密码规则

- 密码长度 12～128 位。
- 至少包含字母和数字。
- 不能包含完整登录用户名。
- 拒绝已冻结的常见弱密码列表。
- 最近 5 个历史密码不能重复使用。
- 不实施周期性强制过期。
- 新管理员使用一次性临时密码，首次登录必须修改。
- 超级管理员重置密码后，新密码仍是临时密码。
- 停用账号重新启用时必须同时设置新的临时密码，不能继续使用旧密码。
- 密码、令牌和密码哈希不得写入业务日志、审计摘要、错误响应或前端持久化状态。

### 3.6 首次改密和自行改密

- 临时密码登录后只签发受限会话。
- 受限会话只能访问修改密码和退出登录接口。
- 前端必须直接进入“设置新密码”页面；手工输入其他 URL 不能绕过。
- 所有管理员均可从右上角账号菜单进入“修改密码”。
- 自行改密必须提交当前密码、新密码和确认密码。
- 修改或重置成功后，该账号全部旧会话立即失效，并跳转登录页。

### 3.7 登录会话

- 同一管理员允许同时在多个浏览器或设备登录。
- 普通管理员会话固定最长 120 分钟。
- 不提供“记住我”，不做无限自动续期。
- 账号停用、密码修改、密码重置、重新启用或未来角色变化时，全部旧会话必须立即失效。
- 会话失效必须使用账号级认证版本控制，不能依赖逐个枚举 JWT。
- `/admin/auth/me` 是权限和账号状态的服务端事实来源；前端不得在调用失败时继续信任旧权限缓存。

### 3.8 登录失败锁定

- 同一有效管理员账号连续 5 次密码错误后锁定 15 分钟。
- 成功登录后失败次数清零。
- 锁定期间即使密码正确也拒绝登录。
- 超级管理员可以提前解除普通管理员锁定。
- 超级管理员自身只能等待自动解锁或通过受控服务器命令恢复。
- 登录响应不得帮助攻击者区分“用户名不存在”和“密码错误”；详细原因只进入安全审计。

### 3.9 高风险操作再认证

超级管理员执行以下动作前必须再次验证自己的当前密码：

- 新建管理员。
- 启用或停用管理员。
- 重置管理员密码。
- 解除临时锁定。

再认证成功状态最长保持 10 分钟，并绑定当前管理员、认证版本和当前登录会话。前端只在内存中持有短时凭据，页面刷新后重新验证。

### 3.10 管理员安全审计

以下事件永久保留且不提供删除接口：

- 登录成功、登录失败和退出登录。
- 管理员创建。
- 管理员启用、停用。
- 管理员密码重置、自行改密。
- 临时锁定、自动解锁和人工解锁。
- 未来发生的预设角色变更。
- 应急运维恢复操作能够接入时，也必须留下来源明确的记录。

每条审计至少记录：

- 动作代码、执行结果和内部原因代码。
- 操作者管理员 ID；登录失败时允许为空。
- 目标管理员 ID；未知用户名登录失败时允许为空。
- 尝试登录用户名的规范化值。
- 请求 ID、来源 IP、User-Agent 和服务端时间。
- 不包含密码、令牌、密码哈希或完整敏感请求体的脱敏摘要。

审计访问边界：

- 题库业务审计：`quiz_admin` 和 `super_admin` 可见。
- 管理员安全审计：仅 `super_admin` 可见。
- 管理员安全审计不可修改、不可删除、永久保留。

### 3.11 网络边界

- Admin 页面和 `/admin/*` 接口只允许内网、Tailscale 或其他受控网络访问。
- 网络限制由反向代理、防火墙或零信任接入层执行，不在业务数据库维护 IP 白名单。
- 不实现 TOTP、短信或其他动态验证码。

## 4. 管理员账号状态模型

账号状态由多个正交字段组成，前端不得用单一字符串覆盖真实安全状态：

| 条件 | 展示状态 | 登录行为 | 可执行管理动作 |
|---|---|---|---|
| `is_active=false` | 已停用 | 拒绝 | 使用新临时密码重新启用 |
| `is_active=true` 且 `locked_until>now` | 临时锁定 | 拒绝 | 等待到期或超级管理员解锁 |
| `is_active=true` 且 `must_change_password=true` | 待首次改密 | 只允许受限登录 | 完成首次改密 |
| `is_active=true` 且未锁定、无需改密 | 正常 | 正常登录 | 停用、重置密码 |

状态不变量：

- 停用不删除管理员或历史引用。
- 解除锁定不自动启用已停用账号。
- 重新启用必须重置临时密码、清空失败次数并递增认证版本。
- 密码修改和重置必须清空失败次数、解除临时锁定并递增认证版本。
- 超级管理员不能通过普通管理接口进入停用状态。

## 5. 目标数据模型

最终字段名以迁移设计评审为准，但必须覆盖以下语义。

### 5.1 `admin_user` 扩展

| 字段 | 语义 |
|---|---|
| `username` | 规范化、不可修改、大小写不敏感唯一的登录名 |
| `display_name` | 必填管理员显示名 |
| `role` | `super_admin` 或 `quiz_admin` |
| `is_active` | 是否允许登录和继续调用后台接口 |
| `must_change_password` | 是否只能进入首次改密流程 |
| `auth_version` | 账号级会话版本；安全变更时递增 |
| `failed_login_attempts` | 连续密码错误次数 |
| `locked_until` | 临时锁定截止时间 |
| `last_login_at` | 最近成功登录时间 |
| `last_login_ip` | 最近成功登录来源的规范化 IP |
| `password_changed_at` | 最近密码设置时间 |

数据库必须增加“最多一个 `super_admin`”约束或等价强一致保护。应用启动和迁移预检还必须验证“至少一个有效 `super_admin`”。

### 5.2 管理员密码历史

建立独立密码历史模型，至少包含管理员 ID、密码哈希和创建时间。业务层只保留并比较最近 5 个哈希；不得存储明文密码或可逆密文。

### 5.3 管理员安全审计表

建立独立于人社和题库领域的管理员安全审计表，支持按操作者、目标账号、动作、结果、时间和请求 ID 查询。

审计表只允许追加，不提供更新和删除服务。现有 `RensheAuditLog` 中 `admin_account.*` 历史事件必须制定一次性迁移或兼容查询方案，不能在新页面中静默丢失。

## 6. 目标 Backend 契约

以下为本轮已经冻结并实现的契约；请求/响应 Schema、错误码、限流和幂等语义必须继续保持一致。

### 6.1 管理员认证

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/admin/auth/login` | 正常或临时密码登录，返回正常/受限会话状态 |
| `GET` | `/admin/auth/me` | 返回管理员、显示名、固定角色、权限和是否必须改密 |
| `POST` | `/admin/auth/logout` | 注销当前会话 |
| `POST` | `/admin/auth/change-password` | 使用当前密码修改本人密码；受限会话也可调用 |
| `POST` | `/admin/auth/reauth` | 高风险操作前再次验证超级管理员当前密码 |

### 6.2 管理员账号

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/admin/settings/admins` | 分页、搜索和筛选管理员 |
| `POST` | `/admin/settings/admins` | 新建 `quiz_admin` 和临时密码 |
| `PATCH` | `/admin/settings/admins/{admin_id}` | 仅编辑普通管理员显示名等允许字段 |
| `POST` | `/admin/settings/admins/{admin_id}/disable` | 停用账号并立即失效全部会话 |
| `POST` | `/admin/settings/admins/{admin_id}/enable` | 使用新临时密码重新启用 |
| `POST` | `/admin/settings/admins/{admin_id}/password-reset` | 重置普通管理员临时密码 |
| `POST` | `/admin/settings/admins/{admin_id}/unlock` | 解除普通管理员临时锁定 |

明确不提供管理员删除接口，也不提供创建/提升 `super_admin` 的接口。

### 6.3 安全审计

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/admin/settings/security-audit` | 超级管理员分页查询永久安全审计 |

所有写接口必须验证：超级管理员身份、10 分钟内有效的再认证状态、目标不是超级管理员、请求版本/幂等边界以及审计写入结果。

### 6.4 ADM-00 契约冻结记录（2026-08-15）

- 角色代码固定为 `super_admin`、`quiz_admin`；旧 `admin` 只允许在迁移中转换，不再出现在新请求或响应中。
- 管理员写接口统一使用 `X-Reauth-Token` 头传递再认证凭据；再认证凭据仅存服务端短期缓存，成功后最多 10 分钟有效，并绑定管理员 ID、当前会话 `jti` 和 `auth_version`。
- 登录成功响应至少包含 `access_token`、`expires_in`、`admin`、`permissions`、`session_mode`（`normal`/`restricted`）和 `must_change_password`；受限会话只能调用 `me`、`change-password`、`logout`。
- 管理员对象至少包含 `id`、`username`、`display_name`、`role`、`is_active`、`must_change_password`、`locked_until`、`last_login_at`、`created_at`、`updated_at`。
- 新建和重置/启用接口返回一次性 `temporary_password`，响应之后不再重复返回；请求体不接受调用方指定超级管理员角色。
- 新建、重新启用和密码重置必须携带 16～64 位 `Idempotency-Key`。Admin 每次用户动作生成新 UUID 且不持久化；Backend 只保存 SHA-256 摘要。相同操作者、动作和键已经成功后返回 `40201 / HTTP 409`，不得再次修改凭据或再次返回临时密码；数据库部分唯一索引负责并发兜底。
- 错误语义冻结为：未认证 `40100`、无权限 `40101`、参数校验 `40001`、业务状态不允许 `40200`、并发/重复 `40201`、限流 `40202`；登录失败、账号不存在、账号停用和锁定对外统一使用 `40100`，详细原因只入安全审计。
- `PATCH /admin/settings/admins/{admin_id}` 只允许修改普通管理员 `display_name`；停用、启用、重置密码、解锁使用独立 POST 动作接口。保留旧 `PUT` 路由仅作兼容转发，不扩展权限。
- 所有列表接口使用现有 `PaginatedData` 结构；安全审计筛选参数为 `actor_admin_id`、`target_admin_id`、`action`、`result`、`username`、`request_id`、`started_at`、`ended_at`、`page`、`page_size`。
- 角色/API 验收矩阵以本文第 10 节为准；隐藏菜单不能替代 Backend 依赖校验，`/admin/auth/me` 失败时前端必须清空认证状态。
- 迁移预检允许 `admin_user` 完全为空这一种干净安装状态；一旦存在任意管理员记录，就必须恰好存在一个且启用的 `super_admin`。干净安装在迁移后由 bootstrap 和就绪验收保证创建唯一有效超级管理员。
- 干净安装由 bootstrap 创建的首个 `super_admin` 初始化密码同样视为临时凭据，首次登录必须完成改密后才能进入业务后台；初始化流程不得把部署时输入的密码静默视为长期正式密码。

## 7. 目标 Admin 页面

### 7.1 路由和菜单

仅 `super_admin` 显示：

```text
系统管理
├── 管理员账号
└── 安全审计
```

`quiz_admin`：

### 7.2 管理员账号页

- 按用户名/显示名搜索。
- 按角色、启停状态、锁定状态和首次改密状态筛选。
- 列表列：ID、用户名、显示名、角色、综合状态、最近登录、创建时间。
- 新建题库管理员。
- 编辑普通管理员显示名。
- 停用、重新启用、重置密码和解除锁定。

### 7.3 首次改密页

- 不能通过侧边栏或手工 URL 离开到业务页面。
- 显示临时密码必须更换的明确原因。

- 前端提示密码规则，但最终以 Backend 校验为准。
- 成功后清理本地认证状态并跳回登录页。

### 7.4 右上角账号菜单

- 显示管理员姓名和角色。
- 提供“修改密码”和“退出登录”。
- 修改密码成功后清理全部本地状态并重新登录。

### 7.5 安全审计页

- 按操作者、目标账号、动作、结果、起止时间和请求 ID 筛选。
- 展示来源 IP、User-Agent 摘要、时间和脱敏结果原因。
- 只读、不可删除。
- 第一期不提供批量删除或前端改写能力。

## 8. 旧数据迁移规则

### 8.1 迁移前预检

- 统计现有 `super_admin` 和 `admin` 数量、启停状态及重复大小写用户名。
- 阻断存在零个或多个超级管理员的异常数据库。
- 阻断规范化后用户名冲突，输出明确冲突清单，禁止自动覆盖。
- 备份 `admin_user`、关联审计和有效会话所需数据。

### 8.2 数据转换

- 唯一 `super_admin` 保持启用和原角色。
- 旧 `admin` 全部转换为 `quiz_admin`。
- 所有转换后的旧普通管理员默认停用。
- 递增旧普通管理员的认证版本，使全部旧会话失效。
- 旧普通管理员标记为需要临时密码改密；只有超级管理员重置密码并启用后才可登录。
- 现有账号显示名缺失时以用户名安全回填，后续由超级管理员确认普通管理员显示名。
- 不自动创建任何新普通管理员。
- 不物理删除旧管理员或其业务引用。

### 8.3 约束切换

- 将旧角色约束从 `super_admin/admin` 切换为 `super_admin/quiz_admin`。
- 增加规范化用户名唯一约束。
- 增加最多一个超级管理员的数据库级保护。
- 新字段按“新增可空 → 回填 → 校验 → 设为非空”的顺序迁移，避免半迁移状态。

### 8.4 回滚边界

- 回滚代码不能自动重新启用已停用的旧管理员。
- 回滚不能恢复已失效的会话或旧密码。
- 如果数据库结构必须降级，需要单独确认角色映射和安全字段数据保留策略。
- 正式迁移前必须在生产等价副本完成 `upgrade -> 验证 -> downgrade/恢复 -> upgrade` 演练。

6. 旧账号迁移、受控网络、应急恢复、自动化和生产等价 UAT 均有可复查证据。
