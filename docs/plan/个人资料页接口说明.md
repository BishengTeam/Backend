# 前端个人资料页 — 接口与字段说明

> 接口前缀: `/api/user`  
> 聚合入口: `GET /api/user/profile`

---

## 页面展示字段

调用 `GET /api/user/profile` 返回全部字段，一次拿到，无需多次请求。

### 基础信息

| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | string | 明文，不可编辑 |
| `created_at` | string | 注册时间 |

### Level 1 — 可自由编辑，不审核

| 字段 | 类型 | 脱敏 | 可输入 | 说明 |
|------|------|------|--------|------|
| `nickname` | string | — | ✅ | 最长 64 字符 |
| `email` | string | — | ✅ | 最长 128 字符 |
| `phone` | string | `138****1234` | 微信解密 | 不手动输入 |

### Level 2 — 实名认证

| 字段 | 类型 | 脱敏 | 可输入 | 说明 |
|------|------|------|--------|------|
| `user_type` | `student` / `enterprise` | — | ✅ | 决定展示学生还是企业子表单 |
| `real_name` | string | — | ✅ | |
| `id_card` | string | `5101****1237` | ❌ | 脱敏展示，不用于输入 |
| `id_card_raw` | string | — | ❌ | **用户端始终 null**，仅管理端返回明文 |
| `id_card_front_oss` | string | — | ✅ | 图片上传 OSS key |
| `id_card_back_oss` | string | — | ✅ | 图片上传 OSS key |
| `gender` | string | — | ❌ | 后端自动推导，只读展示 |
| `age` | int | — | ❌ | 后端自动推导，只读展示 |
| `census_register` | string | — | ❌ | 后端自动推导，只读展示 |
| `identity_status` | `pending`/`verified`/`rejected` | — | ❌ | 审核状态 |

### Level 2 — 学生信息

出现条件: `user_type = student`

| 字段 | 类型 | 脱敏 | 可输入 | 说明 |
|------|------|------|--------|------|
| `education` | string | — | ✅ | 如「本科」，最长 32 |
| `school` | string | — | ✅ | 最长 128 |
| `major` | string | — | ✅ | 最长 128 |
| `student_card_oss` | string | — | ✅ | 图片上传 OSS key |
| `student_status` | `pending`/`verified`/`rejected` | — | ❌ | 审核状态 |

### Level 2 — 企业信息

出现条件: `user_type = enterprise`

| 字段 | 类型 | 脱敏 | 可输入 | 说明 |
|------|------|------|--------|------|
| `organization` | string | — | ✅ | 最长 256 |
| `enterprise_status` | `pending`/`verified`/`rejected` | — | ❌ | 审核状态 |

## 编辑接口

### 基础资料编辑（即时生效，不审核）

```
PUT /api/user/profile
{
    "nickname": "新昵称",    // 可选
    "email": "a@b.com",      // 可选
    "phone": "13800138000"   // 可选（通常通过微信授权解密获取）
}
```

### 实名认证提交（触发审核）

```
POST /api/user/identity
{
    "user_type": "student",                         // student 或 enterprise
    "real_name": "张三",
    "id_card_number": "510106199001011237",         // 18 位
    "id_card_front_oss": "oss://front.jpg",
    "id_card_back_oss": "oss://back.jpg"
}
```

### 学生信息提交（触发审核，需先有实名）

```
POST /api/user/student
{
    "education": "本科",
    "school": "四川大学",
    "major": "计算机科学",
    "student_card_oss": "oss://student.jpg"
}
```

### 企业信息提交（触发审核，需先有实名）

```
POST /api/user/enterprise
{
    "organization": "某公司"
}
```

## 前端表单逻辑

```
个人资料页加载
  └─ GET /api/user/profile  ← 一次拿到所有数据

编辑区结构:
  ┌─ Level 1: 昵称 / 邮箱 / 手机号
  │    └─ PUT /api/user/profile
  │
  ├─ Level 2 实名: 用户类型 / 姓名 / 身份证号
  │    ├─ 身份证号输入后 → 自动展示 gender / age / census_register（只读）
  │    ├─ 身份证正/反面照片上传
  │    └─ POST /api/user/identity
  │
  ├─ 学生信息（user_type=student 时展示）
  │    ├─ 学历 / 学校 / 专业 / 学生证上传
  │    └─ POST /api/user/student
  │
  └─ 企业信息（user_type=enterprise 时展示）
       ├─ 单位名称
       └─ POST /api/user/enterprise
```

### 交互规则

| 规则 | 说明 |
|------|------|
| 性别/年龄/户籍 | 后端根据身份证号计算，前端**只读展示**，不提供输入框 |
| 学生/企业互斥 | 选择 student 显示学生子表单，选择 enterprise 显示企业子表单 |
| 审核状态 | `pending` → 显示「审核中」遮罩，不可编辑；`rejected` → 可重新提交 |
| 修订次数 | Level 2 最多修改 5 次，30 天后自动重置 |
| 手机号/身份证 | 用户端始终脱敏，`id_card_raw` 始终 null |
| snapshot 恢复 | 审核通过后再修改 → 旧值自动保存为快照；被驳回 → 自动恢复旧值 |
