> 日期：2026-06-02
> 状态：计划中

---

## 一、定位

冒烟测试（smoke test）在**服务部署后**运行，确认所有模块的核心端点可正常响应。与集成测试（`tests/integration/db/`）的区别：

| 维度 | 集成测试 | 冒烟测试 |
|------|----------|----------|
| 测什么 | 业务逻辑正确性 | 服务是否存活 |
| 怎么测 | Service 层 + 真实 DB | HTTP 请求到运行中容器 |
| 依赖 | TEST_DATABASE_URL | `http://localhost:8000` |
| 数据 | 自己造 + 自己清 | 不造不写，只读 |
| 深度 | 多场景（正常/异常/边界） | 1 端点 × 1 场景 |
| 运行时机 | 开发 / CI | 部署后 |

## 三、不覆盖

以下端点有破坏性副作用，不纳入冒烟：

| 端点 | 原因 |
|------|------|
| POST/PUT/DELETE 所有写操作 | 修改/删除生产数据 |
| `POST /admin/orders/{id}/refund` | 退款不可逆 |
| `POST /admin/quiz/imports/csv`、`POST /admin/quiz/imports/json` | 文件上传，副作用大 |
| `GET /admin/users/export` | 文件型响应，冒烟价值低 |
| `GET /admin/orders/export` | 同上 |
| `GET /admin/orders/reconciliation` | 数据敏感，避免误读 |

## 四、执行方式

- 单文件脚本：`tests/smoke/test_admin_smoke.py`
- 运行命令：`python3 tests/smoke/test_admin_smoke.py`
- 目标服务：`http://localhost:8000`
- 依赖：`httpx`（`pip install httpx`）

### 认证流程

```
POST /admin/auth/login  →  拿到 access_token
    ↓
Bearer {token} 注入后续所有请求头
```

### 判定标准

```
✅ PASS  status_code == 200  AND  body["code"] == 0  AND  data 非空
❌ FAIL  以上任意条件不满足
```

### 输出格式

```
=== Admin Smoke Test ===
Target: http://localhost:8000
================================
✅ POST /admin/auth/login          (102ms)
✅ GET  /admin/auth/me             (45ms)
✅ GET  /admin/users               (87ms)
...
--------------------------------
Result: 14/14 passed (2.3s)
```
