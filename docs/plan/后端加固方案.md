### 1.1 补充 rate limiting

**现状**: 零限流。`/api/auth/login`、`/admin/auth/login` 可被暴力枚举。

**方案**: 引入 `slowapi`（基于 `limits` 库，与 FastAPI 集成成熟）。

- 登录端点：`5/minute` per IP
- 全站 API：`100/minute` per IP（泛限流保护）  
- 敏感操作（支付、退款）：更严格限流

**实施**:
```

app/middleware/ 下新增: rate_limit.py
main.py 中将 limiter 注册为 middleware
```

**具体实现**:

```python
# app/middleware/rate_limit.py

from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
```

在 `main.py` 中注册：
```python

app.state.limiter = limiter
app.add_middleware(SlowAPIMiddleware)
```

在需要限流的端点加装饰器：

### 1.2 移除 SecurityMiddleware 的正则检测

**现状**: `SecurityMiddleware` 用正则匹配 URL/query string 的 SQL 注入模式，不检查 JSON body，易误触发。真正的防护依赖 SQLAlchemy 的参数化查询（已到位）和 Pydantic 的严格类型校验（已到位）。

**方案**: 重构 `SecurityMiddleware` 为 `SecureHeadersMiddleware`，只保留删除响应敏感头的功能，去掉 SQL/XSS 正则检测。

**具体实现**:

```python
# app/middleware/security.py
from fastapi import Request
from starlette.middleware.base import BaseHTTPMiddleware

SENSITIVE_HEADERS = {"authorization", "cookie", "x-auth-token"}


class SecureHeadersMiddleware(BaseHTTPMiddleware):
    """Strip sensitive headers from responses."""

    async def dispatch(self, request: Request, call_next):
        response = await call_next(request)
        for header in SENSITIVE_HEADERS:
            if header in response.headers:
                del response.headers[header]
        return response
```

SQL 注入防护依赖 SQLAlchemy 参数化查询 + Pydantic 校验。如需 WAF 级别防护，在反向代理层（nginx/openresty）配置。

### 1.3 JWT_SECRET 默认值硬阻断

**现状**: `docker-compose.yml` 中 `JWT_SECRET=${JWT_SECRET:-change-me-in-production}` —— 如果运维忘记在 `.env` 中设置，线上运行的 JWT secret 就是字符串 `change-me-in-production`。

**方案**:

1. docker-compose 去掉默认值，改为 `${JWT_SECRET:?err}`（bash 参数扩展，未设置时直接报错退出）
2. 在 Settings 类中增加启动校验：生产环境禁止使用弱 secret

**具体实现**:

修改 `docker-compose.yml`:
```yaml
# 改前
- JWT_SECRET=${JWT_SECRET:-change-me-in-production}

# 改后 —— docker-compose 的 variable substitution 不支持 :? 语法，
# 改用 Compose 的 required 机制或在 entrypoint 中校验
- JWT_SECRET=${JWT_SECRET}
```

在 `app/core/config.py` 中增加启动校验：
```python
from pydantic import field_validator

class Settings(BaseSettings):
    ...
    JWT_SECRET: str
    
    @field_validator("JWT_SECRET")
    @classmethod
    def validate_jwt_secret(cls, v: str) -> str:
        if len(v) < 32:
            raise ValueError("JWT_SECRET must be at least 32 characters")
        if v in {"change-me-in-production", "change-me", "your-secret-key"}:
            raise ValueError("JWT_SECRET must not be a default/placeholder value")
        return v
```

### 2.1 request_id 注入日志链路

**现状**: `RequestIDMiddleware` 设置了 `request.state.request_id`，但 `LOG_FORMAT` 没有引用它。日志中看不到请求追踪 ID。

**方案**: 使用 `logging.Filter` + `contextvars` 将 request_id 注入每行日志。

**具体实现**:

```python
# app/core/logging.py
import logging
import sys
from contextvars import ContextVar

request_id_var: ContextVar[str] = ContextVar("request_id", default="-")

LOG_FORMAT = (
    "%(asctime)s | %(levelname)-8s | %(request_id)s | %(name)s:%(lineno)d | %(message)s"
)


class RequestIDFilter(logging.Filter):
    def filter(self, record):
        record.request_id = request_id_var.get()
        return True


def setup_logging() -> None:
    level = logging.DEBUG if settings.APP_DEBUG else logging.INFO
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(logging.Formatter(LOG_FORMAT))
    handler.addFilter(RequestIDFilter())
    
    root = logging.getLogger()
    root.setLevel(level)
    root.handlers = [handler]

    for lib in ("uvicorn", "sqlalchemy.engine", "httpx"):
        logging.getLogger(lib).setLevel(logging.WARNING)
```

修改 `RequestIDMiddleware`，把 request_id 写入 contextvar:
```python
# app/middleware/request_id.py
from app.core.logging import request_id_var

class RequestIDMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))
        request.state.request_id = request_id
        token = request_id_var.set(request_id)
        try:
            response = await call_next(request)
            response.headers["X-Request-ID"] = request_id
            return response
        finally:
            request_id_var.reset(token)
```

### 2.3 健康检查增强

**现状**: `/health` 只返回 `{"code":0}`，不检查任何依赖。

**方案**: 增加数据库和 Redis 连通性检测。

```python
@app.get("/health")
async def health():
    db_ok = await _check_db()
    redis_ok = await _check_redis()
    all_ok = db_ok and redis_ok
    return {
        "code": 0 if all_ok else 50000,
        "status": "ok" if all_ok else "degraded",
        "checks": {
            "database": "ok" if db_ok else "unavailable",
            "redis": "ok" if redis_ok else "unavailable",
        },
    }

async def _check_db() -> bool:
    try:
        async with get_db_ctx() as db:
            await db.execute(text("SELECT 1"))
        return True
    except Exception:
        return False

async def _check_redis() -> bool:
    try:
        await redis_client.ping()
        return True
    except Exception:
        return False
```

### 3.1 refresh token 竞态修复

**现状**: `AuthService.refresh()` 中 READ (get) 和 DELETE (pipeline delete) 之间存在竞态窗口。两个并发请求同时 `get` 到同一个 token，都会成功创建新 token。

```
请求A: GET token_key → user_id (成功)
请求B: GET token_key → user_id (成功)    ← 竞态：A 还没删
请求A: SET new_key, DEL old_key
请求B: SET new_key, DEL old_key          ← A 的 new_key 被覆盖
```

**方案**: 使用 Redis `GETDEL` 原子操作替代 `GET` + `DELETE`。

**具体实现**:

```python
# app/services/auth.py — refresh 方法
async def refresh(self, refresh_token: str) -> RefreshResponse:
    key = f"{REFRESH_TOKEN_PREFIX}{refresh_token}"
    user_id_raw = await redis_client.getdel(key)  # 原子：读 + 删
    if user_id_raw is None:
        raise UnauthorizedException("refresh_token 无效或已过期")
    
    user_id = int(user_id_raw)
    async with get_db_ctx() as db:
        user = await db.get(User, user_id)
        if user is None or not user.is_active:
            raise UnauthorizedException("账号不存在或已注销")
        
        new_access_token = create_access_token(user.id, user.openid)
        new_refresh_token = create_refresh_token()
        await redis_client.setex(
            f"{REFRESH_TOKEN_PREFIX}{new_refresh_token}",
            REFRESH_TOKEN_TTL,
            user.id,
        )
        # 旧 token 已在 getdel 中删除，无需再 delete
    
    return RefreshResponse(
        access_token=new_access_token,
        refresh_token=new_refresh_token,
        expires_in=settings.JWT_EXPIRE_MINUTES * 60,
    )
```

**注意**: `GETDEL` 需要 Redis >= 6.2.0（`redis:7-alpine` 满足要求）。

```python
# app/schemas/admin.py

ROLE_PERMISSIONS: dict[str, list[str]] = {
    "super_admin": ["*"],  # 所有权限
    "content_editor": [
        "dashboard:view",
        "quiz:list", "quiz:write", "quiz:import",

        "dashboard:view",
        "order:list", "order:write",

        "dashboard:view",
        "user:list", "order:list",
        "quiz:list", "content:list", "course:list",
    ],
}
```

2. **新增 `require_permission` 依赖**:

```python
# app/middleware/auth.py

from app.core.exceptions import ForbiddenException


async def require_permission(permission: str):
    """Dependency factory: returns a dependency that checks permission."""
    async def _check(admin=Depends(get_current_admin)):
        if admin.role == "super_admin":
            return admin
        allowed = ROLE_PERMISSIONS.get(admin.role, [])
        if permission not in allowed:
            raise ForbiddenException(f"缺少权限: {permission}")
        return admin
    return _check
```

3. **在端点使用**:

```python
@router.delete("/orders/{order_id}")
async def delete_order(
    order_id: int,
    admin=Depends(require_permission("order:write")),
):
    ...
```

4. **修改 AdminLoginResponse**，只返回该 role 对应的权限:

```python
# app/services/admin_auth.py — login 方法
from app.schemas.admin import ROLE_PERMISSIONS

return AdminLoginResponse(
    access_token=access_token,
    expires_in=settings.JWT_EXPIRE_MINUTES * 60,
    admin=AdminInfo.model_validate(admin),
    permissions=ROLE_PERMISSIONS.get(admin.role, []),
)
```

### 4.2 优雅关闭

**现状**: `lifespan` 中 yield 后只 cancel 了 `cleanup_loop`，没有等待进行中的请求完成、关闭数据库连接池、关闭 Redis 连接。

**方案**:

```python
# app/main.py
from app.core.database import engine

@asynccontextmanager
async def lifespan(app: FastAPI):
    setup_logging()
    cleanup_task = asyncio.create_task(cleanup_loop())
    
    logger.info("Application startup complete")
    yield
    
    # 1. 停止后台任务
    logger.info("Shutting down background tasks...")
    cleanup_task.cancel()
    try:
        await cleanup_task
    except asyncio.CancelledError:
        pass
    
    # 2. 关闭数据库连接池
    logger.info("Closing database connections...")
    await engine.dispose()
    
    # 3. 关闭 Redis 连接池
    logger.info("Closing Redis connections...")
    await redis_client.close()
    
    logger.info("Application shutdown complete")
```
