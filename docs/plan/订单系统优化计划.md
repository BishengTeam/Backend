# 订单系统优化计划

> 目标：订单系统从「认证报名专用」改造为「多业务通用」，支持认证报名、课程购买及未来新增业务。

---

## 1. 模型改造

### 1.1 加 `order_kind` 字段

```python
# app/domain/order/src/model/order.py
order_kind: Mapped[str] = mapped_column(String(32), nullable=False, index=True)
# 值: "certification" | "course"
```

### 1.2 `cert_type` → `product_type`

```python
# 原来
cert_type: Mapped[str]

# 改为
product_type: Mapped[str] = mapped_column(String(64), nullable=False)
```

### 1.3 `candidate_*` 三个字段删除，迁入 `extra_data`

认证报名的考生信息不再占顶层列，统一走 JSON：

```json
// extra_data
{
    "candidate_name": "张三",
    "candidate_phone": "13800138000",
    "candidate_idcard": "510106199001011237"
}
```

### 1.4 `inventory_id` 保持 nullable

课程购买不需要库存，`inventory_id` 为 null 时跳过库存操作。

### 模型最终结构

```python
class Order(Base):
    user_id: int
    order_kind: str           # "certification" | "course"
    product_type: str          # 商品标识
    price: int                 # 分
    status: str                # pending | paid | completed | refunded | closed
    out_trade_no: str | None
    transaction_id: str | None
    inventory_id: int | None   # 仅认证报名时锁定
    paid_at: datetime | None
    expires_at: datetime | None
    closed_at: datetime | None
    close_reason: str | None
    extra_data: dict | None    # JSON — 所有业务专属字段
    attachments: list | None   # JSON
```

### 迁移

需新增 Alembic 迁移脚本：
- 加 `order_kind` 列（NOT NULL，历史数据回填 `"certification"`）
- 加 `product_type` 列，从 `cert_type` 复制数据后删 `cert_type`
- `candidate_name` / `candidate_phone` / `candidate_idcard` 改为 nullable
- PriceConfig 表的 `cert_type` 同步改为 `product_type`

## 2. 状态机

### 2.1 加 `pending → completed` 边

```python
# app/domain/order/src/rule/order_rules.py
ORDER_STATUS_TRANSITIONS = {
    "pending":   {"paid", "closed", "completed"},  # + completed
    "paid":      {"completed", "refunded"},
    "completed": {"refunded"},
    "refunded":  set(),
    "closed":    set(),
}
```

0 元订单（积分兑换等）创建后直接 `completed`。

## 4. 支付回调

### 4.1 按 `order_kind` 分流

```python
# app/services/payment.py — _handle_callback_inner
if order.order_kind == "course":
    apply_order_status_transition(order, "completed")  # 直购，自动完成
else:
    apply_order_status_transition(order, "paid")        # 认证，等待审核
```

### 4.2 库存生命周期（2026-07-14 已实现）

```text
创建订单：available -> locked    action=lock
支付成功：locked -> sold         action=confirm
超时关闭：locked -> available    action=release
支付退款：sold -> available      action=refund
```

- 同一订单的同一种库存动作只允许写入一次
- 重复支付、退款和超时处理不会重复修改库存
- 已确认售出的库存不能再走锁定释放流程
- 同一用户在同一批次只能存在一个 `pending/paid/completed` 订单

## 5. 审核接口（新增）

### 5.1 接口

```
PUT /admin/orders/{id}/review
{
    "action": "approve" | "reject_registration" | "reject_and_refund",
    "comment": "理由"
}
```

### 5.2 行为

| action | 状态变化 | 副作用 |
|--------|---------|--------|
| `approve` | `paid` → `completed` | 无 |
| `reject_registration` | `paid` → `paid` | 订单保持 paid，驳回理由写入 extra_data，用户可修改报名信息重提 |
| `reject_and_refund` | `paid` → `refunded` | 调微信退款 + 退回已售库存（sold → available） |

### 5.3 权限

`require_permission("order:write")`

## 6. 超时清理

### 6.1 定期关闭过期订单

```python
# app/services/cleanup.py
# cleanup_loop 中加入:
await OrderTimeoutCloseService().close_expired_pending_orders()
```

扫描间隔建议 5 分钟。

### 6.2 支付超时时长

`ORDER_PAYMENT_EXPIRE_MINUTES` 当前为 30 分钟，根据文档改为 1440（1 天）：

```python
# app/domain/order/src/rule/order_rules.py
ORDER_PAYMENT_EXPIRE_MINUTES = 1440  # 1 天
```

## 8. 不影响的部分

- 支付预下单 / 回调签名验证逻辑不变
- 退款统一执行微信退款、本地状态变更和已售库存退回，使用确定性的退款单号保证重试幂等
- 超时关闭逻辑不变
- `extra_data` 的 `validate_extra_data` 校验不变（按 product_type 校验 schema）
- 现有 `POST /api/orders` 请求体向后兼容（candidate_* 字段改为从 extra_data 读取，不传则使用旧字段做 fallback）
