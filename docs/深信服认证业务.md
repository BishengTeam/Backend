# 深信服认证首期

依据甲方提供的 `2026年深信服 认证报名表模板.xlsx`，模板原件随服务保存在 `app/assets/sangfor_registration.xlsx`。报送使用 Sheet1 的13列表头、列序及隐私声明。

本期开放三份下拉目录一致的8个方向：SCSA-S、SCSA-T、SCCA-C、SCSP-S、SCCP-C、SCSE-T、SCSE-S、SCCE-C。其他方向待完整目录确认后适配；服务端阻止未确认方向启用和发布招生。

## 办理流程

1. 后台产品设置中选择已确认报考方向，维护名称、介绍和封面。
2. 创建批次，填写报名起止、考试时间、费用、地点和名额，保存草稿后发布。
3. 游客浏览产品及批次，点击报名时登录。首次提交须本人实名认证通过，并同意认证报名信息处理授权协议。
4. 姓名、身份证由服务端取本人实名记录；方向、考试时间和费用取批次。考生填写名字拼音、姓氏拼音、所属机构、手机和考试券码，邮箱、邮寄地址、备注选填。
5. 创建银行转账订单，沿用现有账户快照、凭证提交、补交、核账和资金异常能力。券码单独存放在 `exam_voucher_code`，不占用平台积分商城的 `coupon_code`，不生成或核销厂商券码。券码有效性由管理员核验。
6. 后台深信服批次工作台通过现有“报名办理”侧边窗先核账、后初审。初审通过后选择记录，二次身份验证后导出报名表。
7. 登记外审结果：通过前检查当前报名版本已成功导出；退回时填写明确原因和补正截止时间。
8. 补正使用原订单，新建报名资料版本；有效补正期内可超过普通报名截止时间。过期、批次终止、退款已审批或资金异常会阻止继续办理。

## 数据和权限

复用 `CertProduct`、`Plan`、`Order` 和现有线下银行账本，无新增数据库表或迁移。深信服结构化报名、独立资料版本、审核及导出摘要保存在订单 `extra_data`，由专用服务在订单行锁和 `revision` 比对下更新。通用下单和通用审核接口无法绕过专用报名校验。

公开接口只返回已上架产品的公开批次字段。个人报名读写按本人鉴权；后台读取沿用 `order:list`，产品、批次维护沿用内容权限，认证管理员新增 `sangfor:review`、`sangfor:export`。核账、退款及收款配置仍使用现有独立财务权限。

退款在订单管理中沿用“审批退款 → 线下实际退款 → 上传凭证并登记银行流水”。退款审批后冻结报名审核、补正和报送，实际退款登记成功后显示已退款。银行退款记录不会由报名审核动作代替。

导出记录保存资料版本、生成时间及文件 SHA256；文件由本次下载取得。姓名、身份证、手机、拼音、券码等使用实际报名数据；考试日期为 Excel 日期值，显示 `yyyy-mm-dd`。所有考生文本按文本单元格导出，避免公式注入。

## 后台界面统一

深信服沿用 NISP 的批次优先布局：搜索筛选、彩色状态、报名办理统计、管理报名及更多操作。批次编辑使用820px分组侧边窗；新建可保存草稿或保存并发布，发布失败后重试复用已创建的草稿。

工作台使用“报名列表／导出记录／退款记录”三个标签。报名列表支持核账及审核快捷筛选、跨页选择和导出前名单确认；导出提交携带选择时的资料版本，服务端在行锁内验证，避免导出补正后的未确认名单。导出记录显示实际生成时间、人员及版本，退款记录仍进入现有订单财务流程办理。报名办理继续复用公共“先核账、后审核”侧边窗，深信服券码、拼音等业务字段保留。

状态统计只由后台接口返回，公开批次不返回审核统计。导出记录读取现有订单内的导出日志，新日志增加统一的导出批号，无数据库迁移。此界面更新需配套更新 Backend 与 Admin（新增导出记录读取接口、创建批次返回草稿ID），Platform 无需改动。

## 上线核对

Backend、Admin、Platform 需配套发布；本次仅提交上传代码。上线前由甲方实际导入13列表验证报送兼容性，并在真实微信中验证游客进入、登录返回、本人实名、报名、转账凭证、补正和审核结果查看。目录之外的方向不开放招生。
