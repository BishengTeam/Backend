# 在线更新与回滚运行手册

## 目标

生产部署保持一次性 Bootstrap 关闭状态，正式服务不获得 Docker Socket。超级管理员在 Admin 中只检查版本和复制命令；实际升级由运维在后台服务器执行独立升级器。

## 后台检查

- 路径：`系统管理 -> 版本与更新`
- API：`GET /api/admin/system/updates/check`
- 权限：仅 `super_admin`
- 外部查询：GitHub `releases/latest`
- 成功缓存：5 分钟
- 页面能力：展示当前/最新版本、资产、Release 说明、预演命令和正式升级命令

后台页面不执行升级，也不展示升级进度。

## 首次安装升级器

从包含 `upgrade_release.sh` 的 deployment bundle 安装：

```bash
sudo install -d -m 0700 /srv/wemini-updater
sudo install -m 0755 \
  /path/to/wemini-deploy-RELEASE/upgrade_release.sh \
  /srv/wemini-updater/upgrade_release.sh
```

后续 Release 会随 deployment bundle 携带新版升级器；一次升级成功后会自动更新 `/srv/wemini-updater/upgrade_release.sh`。

## 预演

```bash
DOCKER_USE_SUDO=1 /srv/wemini-updater/upgrade_release.sh \
  --release RELEASE \
  --deployment-root /srv/wemini-bootstrap-DEPLOYMENT \
  --compose-project COMPOSE_PROJECT \
  --dry-run
```

预演会读取当前部署、检查健康状态和关键活动、下载校验资产、检查压缩包和磁盘空间，但不停服务、不加载数据库变更。

## 正式升级

```bash
DOCKER_USE_SUDO=1 /srv/wemini-updater/upgrade_release.sh \
  --release RELEASE \
  --deployment-root /srv/wemini-bootstrap-DEPLOYMENT \
  --compose-project COMPOSE_PROJECT
```

流程：

1. 锁定升级，禁止并发执行；
2. 校验当前镜像 revision、运行状态和关键活动；
3. 下载四个 Release 资产并校验 SHA256；
4. 校验新镜像 revision；
5. 停止 Backend、quiz-worker 与 Admin，保留 PostgreSQL/Redis；
6. 创建并验证 PostgreSQL custom 备份；
7. 使用恢复公钥加密备份并上传 OSS；
8. 执行新版本 Alembic migration；
9. 原地启动新 Backend、quiz-worker 与 Admin；
10. 通过 `/ready` 和 Admin 健康检查后提交 source pin。

## 维护页

云服务器 Nginx 需要为 API 和 Admin 虚拟主机配置 502/503/504 自动降级：

```nginx
error_page 502 503 504 =503 /wemini-maintenance.html;

location = /wemini-maintenance.html {
    internal;
    root /var/www/wemini;
}
```

`maintenance.html` 已包含在 deployment bundle。升级期间服务不可达时返回 HTTP 503；服务恢复后自动回到正常代理。

## 备份与回滚

- 本地备份：`DEPLOYMENT_ROOT/backups/postgresql/*.dump`
- 本地保留：最近 7 天且至少 7 份
- OSS 前缀：`wemini-backups/postgresql/INSTALLATION_ID/`
- OSS 保留：最近 7 天且至少 7 个加密包
- OSS 加密：随机 AES-256 key + RSA-OAEP-SHA256 恢复公钥

新版本迁移或健康检查失败时，升级器停止新服务、恢复备份、启动旧镜像并重新健康检查。升级日志位于：

```text
/srv/wemini-updater/logs/
```

## 活动预检

默认存在以下情况时拒绝升级：

- 进行中的考试；
- 进行中或暂停的练习；
- quiz-worker 队列非空；
- 近两小时仍有 pending 订单。

紧急修复可显式追加 `--force`。该参数只跳过活动预检，不跳过备份、校验或回滚。
