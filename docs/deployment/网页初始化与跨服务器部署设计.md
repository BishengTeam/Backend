## 1. 目标

为全新服务器提供一条可复查的安装链路：CI 对指定 Backend/Admin Commit 完成质量门禁，将两个镜像包、Compose 部署包和 SHA-256 清单发布到 GitHub Release；运维下载并校验四个资产后导入镜像，通过 SSH 隧道打开一次性网页，填写外部凭据、迁移空数据库、创建首位超级管理员并启动 Backend 和 Admin。

这不是一个常驻“运维控制台”。初始化完成后，匿名入口永久关闭，正式应用只拥有 Secret 只读权限。

## 2. 冻结边界

### 2.1 首版包含

- 独立 `bootstrap` 容器和一次性网页，宿主机端口只绑定 `127.0.0.1`。
- 自动生成数据库密码、JWT Secret、PII Hash Key 和监控 Token。
- 网页接收微信 Secret、微信支付 V3 材料和一组统一阿里云 OSS 凭据；人社材料、题库导入与远端恢复复用该凭据和 Bucket，仅以固定前缀隔离。
- Secret 以 `0600` 权限原子写入宿主机专用目录；正式服务只读挂载。
- 支持 Compose 内置 PostgreSQL/Redis，也支持外部 PostgreSQL/Redis。
- 外部 PostgreSQL 必须是专用空库；Redis DB/命名空间必须未占用。
- GitHub Actions 检出用户明确指定的 Backend/Admin ref，解析并固定完整 Commit SHA。
- CI 在隔离 PostgreSQL 中运行 Backend/Admin 质量门禁，生成两个独立的 `tar.zst` 镜像资产和一个小型 Compose 部署包，并发布不可覆盖的 GitHub Release。
- 生产服务器不克隆源码、不访问容器 Registry、不现场编译；只校验 Release、执行 `docker load` 并运行 Compose。
- 独立 migration job；迁移成功后执行版本化生产种子和创建唯一超级管理员。
- 使用恢复公钥加密完整 Secret、非敏感配置和版本清单，上传统一私有 OSS 的恢复前缀。
- Backend 和 Admin 只绑定宿主机环回地址；公网由既有 HTTPS 网关提供。
- 部署完成状态为 `INSTALLED_PENDING_UAT`；真实微信登录、支付和退款闭环通过后，由超级管理员签署验收。

### 2.2 首版不包含

- Platform 配置、构建、上传、提审或发布。
- 自动安装 Docker、Git、操作系统包、DNS、证书、Nginx/Caddy 或防火墙。
- 迁移已有生产数据库、覆盖已有业务库或从 V2 支付数据升级。
- 网页修改已投产 Secret、密钥轮换或重新开启 `/setup`。
- 网页删除数据库、Docker 卷或 Secret；失败仅支持幂等重试。
- 将 Docker Socket 挂入任何 Web 容器。
- 资源不足时强行阻断；CPU、内存和磁盘只告警，镜像拉取或正式服务启动失败仍终止。

## 3. 威胁模型与安全不变量

1. `/setup` 没有业务账号可用于登录，因此必须同时依赖环回端口和一次性随机 Token。
2. Token 只写入权限 `0600` 的文件，并通过 URL Fragment 交给浏览器；Fragment 不进入 HTTP 请求日志。
3. 初始化页面、状态文件、日志和错误响应不得回显 Secret、私钥、管理员密码、数据库 URL 或恢复包明文。
4. 超级管理员密码只在最终建号步骤进入内存，不写入状态文件、环境文件、恢复包或日志。
5. Secret 使用同目录临时文件、`fsync`、`chmod 0600` 和原子替换；目录固定为 `0700`，拒绝符号链接和越界路径。
6. 一旦完成标记存在，`bootstrap` API 除健康检查外统一返回 `410 Gone`。
7. 正式 Backend/Admin 不挂载 Secret 目录写权限；`bootstrap` 不挂载 Docker Socket。
8. 外部数据库只允许空目标。任何未知表、已有 Alembic 版本或非空 Redis 目标都必须中止，不能提供“仍然继续”。
9. 恢复包先在内存中形成、再使用运维恢复公钥加密。只允许加密载荷落盘或上传 OSS。
10. 初始化状态签名并采用单向阶段迁移；重试只能重复当前或未完成阶段，不能倒退覆盖已完成事实。

## 4. 组件关系

```text
运维终端
  ├─ 下载 GitHub Release 四个资产并核对 SHA-256
  ├─ install_release.sh 导入两个 Commit 镜像
  ├─ bootstrap_server.sh 读取 release-source.env
  │    ├─ 启停 bootstrap 容器
  │    ├─ 核对镜像标签、revision 和发布身份
  │    ├─ 运行 migration/production-seed job
  │    └─ 启动 Backend、quiz-worker、Admin
  └─ SSH -L 18080:127.0.0.1:18080
                    │
                    ▼
             bootstrap Web/API
              ├─ Secret 原子写入
              ├─ 外部配置验证
              ├─ 非敏感状态文件
              ├─ 创建首位超级管理员
              └─ 加密恢复包 → 统一私有 OSS 的恢复前缀

正式运行：
HTTPS Gateway → 127.0.0.1:8000 Backend
HTTPS Gateway → 127.0.0.1:8080 Admin
Backend/Worker ──只读──> Secret 文件
```

## 5. 安装状态机

| 状态 | 含义 | 下一状态 |
|---|---|---|
| `NEW` | 未提交安装配置 | `CONFIGURED` |
| `CONFIGURED` | Secret 和非敏感配置已原子写入，外部静态校验通过 | `QUALITY_RUNNING` |
| `QUALITY_RUNNING` | 正在核对预构建镜像 Commit/revision 和发布身份 | `QUALITY_PASSED` 或留在本状态等待重试 |
| `QUALITY_PASSED` | CI 质量来源、镜像 ID 和发布清单已固定 | `INFRA_READY` |
| `INFRA_READY` | 内置或外部 PostgreSQL/Redis 空目标检查通过 | `MIGRATED` |
| `MIGRATED` | 独立 migration job 到唯一 Alembic head | `AWAITING_ADMIN` |
| `AWAITING_ADMIN` | 网页等待最终管理员用户名和密码 | `ADMIN_CREATED` |
| `ADMIN_CREATED` | 唯一超级管理员已创建，可作为正式种子的创建人 | `SEEDED` |
| `SEEDED` | 版本化生产种子完成，无测试数据 | `RECOVERY_VERIFIED` |
| `RECOVERY_VERIFIED` | 加密恢复包已上传统一 OSS 恢复前缀并核对 SHA-256 | `INSTALLED_PENDING_UAT` |
| `INSTALLED_PENDING_UAT` | Backend/Admin 已启动，但真实微信/支付验收未签字 | `PRODUCTION_ACCEPTED` |
| `PRODUCTION_ACCEPTED` | 技术证据齐全且超级管理员签署 | 终态 |

失败不会建立新状态，只记录脱敏错误码、失败阶段、重试次数和时间。浏览器关闭或服务器重启后，从最后一个完成阶段继续；管理员密码必须重新输入。

## 6. 网页步骤

1. **会话验证**：输入或从 URL Fragment 读取一次性 Token，显示安装 ID。
2. **部署信息**：选择内置/外部数据库，填写 API/Admin HTTPS 域名和外部连接的非敏感部分。
3. **外部凭据**：以密码框或文件上传方式提供微信、支付 V3、统一业务/恢复 OSS 和恢复公钥材料。
4. **安全校验**：验证 PEM、公私钥匹配、V3 Key 恰好 32 字节、URL/域名、Bucket 私有性和只读/写入探针；不能自动验证的项目明确列为 UAT。
5. **自动部署进度**：只展示阶段、Commit、耗时和脱敏错误，不展示命令环境或 Secret。
6. **管理员创建**：迁移和生产种子完成后才展示用户名/强密码表单。
7. **完成**：展示 `INSTALLED_PENDING_UAT`、两端地址、Commit、恢复对象键和 SHA-256；随后关闭初始化 API。

## 7. Secret 与非敏感配置

### 7.1 自动生成

| 文件 | 最低要求 |
|---|---|
| `postgres_password` | 32 随机字节的 URL-safe 表示；仅内置数据库使用，仍纳入恢复包 |
| `jwt_secret` | 至少 64 随机字节 |
| `pii_hash_key` | 至少 64 随机字节；跨服务器恢复时必须保持不变 |
| `quiz_metrics_bearer_token` | 至少 48 随机字节 |

### 7.2 人工提供

- `wechat_secret`
- `wechat_pay_private_key`
- `wechat_pay_api_v3_key`
- `wechat_pay_public_key`
- 统一 OSS Endpoint/Bucket/AccessKey ID/Secret
- 恢复 RSA 公钥 PEM（至少 3072 位，仅保留公钥）
- 外部数据库密码或完整连接 Secret、外部 Redis URL Secret

非敏感运行配置单独写入 `runtime.env`，只允许键白名单，不接受换行、NUL、Shell 展开或任意环境变量名。

## 8. 恢复包格式

首版使用混合加密：随机 AES-256-GCM 数据密钥加密 JSON/TAR 载荷，再用 RSA-OAEP-SHA256 恢复公钥加密数据密钥。信封包含：

- 格式版本和算法标识；
- 安装 ID、创建时间、Backend/Admin Commit；
- 加密数据密钥、Nonce、Tag 和 Ciphertext；
- 明文信封的 SHA-256；
- 对象元数据中的安装 ID 和 SHA-256。

仓库必须同时提供离线解密校验工具。工具只向显式目标目录恢复，并拒绝覆盖现有文件、符号链接和权限过宽的私钥。

## 9. 数据库、迁移和正式种子

- 内置模式由部署 Compose 创建 PostgreSQL 16 和 Redis 7，数据库端口不向宿主机公开。
- 外部模式允许自定义 PostgreSQL 端口，包括 `3306`；连接协议仍必须为 PostgreSQL。
- 空库检查使用 PostgreSQL Catalog，不以“没有 `admin_user`”代替空库。
- Redis 检查只检查配置的 DB/前缀，并使用 `SCAN`，禁止生产 `KEYS`。
- migration job 设置 `RUN_MIGRATIONS=false` 并显式执行 `alembic upgrade head`；正式 Web 同样关闭启动时迁移。
- 新建 `seed_production.py`，仅调用版本化白名单步骤，禁止导入 `seed_testdata`，不得提供 `--force`。
- 首位超级管理员在迁移后、正式种子前创建，并复用现有 PBKDF2 密码哈希实现；需要创建人外键的正式种子引用该管理员。
- 课程模块不初始化任何默认类目或课程；正式种子在写入配置前必须验证 `crs001` 的课程、类目、章节、资料、报名、审计、权益任务、权益记录和课程-题库绑定表均已存在。

## 10. GitHub Release、预构建镜像和发布清单

- `.github/workflows/publish-github-release.yml` 在 CI 中运行 Backend 单元/契约/迁移、隔离 PostgreSQL 集成测试及 Admin 测试/构建。
- CI 为两个镜像写入完整 Commit 标签和 `org.opencontainers.image.revision`，分别 `docker save`、zstd 压缩，避免一个合并资产超过限制。
- 每个 GitHub Release 固定四个资产：Backend 镜像、Admin 镜像、Compose 部署包和 `SHA256SUMS`。单个资产达到 2 GiB 时发布失败。
- 部署包的 `release-source.env` 固定仓库 URL、两个 Commit、镜像名、资产名和内置 SHA-256；不包含源码或 Secret。
- 生产使用 `DEPLOY_SOURCE_MODE=release` 和 `RELEASE_IMAGE_MODE=preloaded`，不需要 Git 仓库；Release Commit 与已有 `source-pins.env` 不一致时拒绝续跑。
- 发布清单记录仓库 URL、Commit SHA、镜像 ID、`github_release` 质量来源和配置指纹。数据库 migration 仍在目标空库独立执行。

人社 `报名信息.xlsx`、`工作经历.xlsx` 不再是整个平台部署的前置条件。缺失时创建空的宿主机模板目录并输出告警；Backend/Admin 可以启动，但人社批次导出会明确失败，补齐两个官方模板后恢复，无需重装平台。

## 11. 网络与正式运行

- `bootstrap`：`127.0.0.1:18080`，仅 SSH 隧道。
- Backend：`127.0.0.1:8000`，由 `api.<domain>` HTTPS 网关代理。
- Admin：`127.0.0.1:8080`，由 `admin.<domain>` HTTPS 网关代理，并要求网关 IP 白名单或 VPN。
- Backend CORS 只允许精确 Admin HTTPS Origin；禁止 `*` 和带凭据的宽泛来源。
- 支付和退款回调使用 API 域名，必须为 HTTPS。

## 12. 部署后 UAT

正式 Backend 提供仅超级管理员可用的部署验收查询/签署 API，Admin 后续增加“系统部署与验收”页面。页面不得查看或修改 Secret。

必须记录以下证据后才允许签署 `PRODUCTION_ACCEPTED`：

- `/health`、`/ready` 和 Worker 心跳；
- 真微信登录；
- 专用 UAT 批次和用户；
- 六类材料私有 OSS 上传、短签和越权拒绝；
- 0.01 元 JSAPI 支付、支付回调或主动查单；
- 全额退款、退款回调或主动查单；
- 恢复包对象版本和 SHA-256；
- 数据库备份和恢复命令已配置。

UAT 数据必须带专用标识，不进入正式统计；退款完成后归档证据。签署操作记录管理员、时间、发布清单摘要和证据摘要，任何未通过项不能被忽略。

## 13. 回滚和失败处理

- 初始化阶段只提供“重试当前步骤”，不提供网页删除或重置。
- Secret 已写入但迁移未开始：修正外部配置后可原子替换尚未锁定的输入。
- 迁移开始后：不得自动删库或 downgrade；保留状态和日志供运维修复后重试。
- 正式服务未切流：停止新容器并保留数据库、Secret、发布清单和恢复包。
- 完成标记一旦写入，重新运行初始化程序只返回已完成状态，不能修改部署。

## 14. 验收底线

- 不能以页面出现、Docker 构建成功或 `/health` 返回 200 代替完整验收。
- 日志扫描必须确认没有 Secret、管理员密码、数据库 URL、完整 OSS 对象签名 URL。
- 必须有中断恢复、重复提交、并发提交、错误 Token、完成后重入和符号链接攻击测试。
- 必须在一台干净服务器或生产等价虚拟机完整执行一次，保存 Commit、测试日志、迁移 head、恢复包校验和 UAT 签字。

## 15. 新服务器最短操作流程

前提：GitHub Actions 已为指定 Backend/Admin Commit 发布四资产 Release；服务器安装 Docker Compose v2、zstd、GitHub CLI并准备 HTTPS 网关。部署用户可直接拥有 Docker 权限，或使用 `DOCKER_USE_SUDO=1` 仅提升 Docker 子命令；禁止用 `sudo` 运行整个脚本。先准备私有部署目录：

```bash
sudo install -d -m 0700 -o "$(id -un)" -g "$(id -gn)" /srv/wemini-bootstrap

mkdir -p /tmp/wemini-release
cd /tmp/wemini-release
gh release download <release-tag> --repo BishengTeam/Backend
sha256sum -c SHA256SUMS
tar -xzf wemini-deploy-<release-tag>.tar.gz
./wemini-deploy-<release-tag>/install_release.sh
```

私有 GitHub 仓库通过只读 Token 登录 `gh`；不需要容器 Registry Token。如果人社模板尚未准备，只会告警并给出稍后补齐目录。

脚本会输出只含环回地址的 SSH 隧道命令和带 Fragment Token 的一次性网址。按页面填写配置，等待脚本输出 `INSTALLED_PENDING_UAT`；随后配置 HTTPS 网关并完成真实 UAT。

Admin 签署 `PRODUCTION_ACCEPTED` 后，在服务器再执行一次同一脚本。脚本只核对数据库中的终态并封存本地签名状态，不重新拉取版本、不重建数据库，也不重开 `/setup`。
