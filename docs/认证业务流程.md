# 认证报名业务流程

## 业务流程图

```mermaid
flowchart TD
    A[微信登录] --> B[提交实名认证]
    B --> C{实名审核}
    C -->|驳回<br/>显示理由，基于旧信息修改| B
    C -->|通过| D[选择认证类型]
    D --> E[填写报名表单]
    E --> F[提交并创建订单<br/>开始1天支付倒计时]
    F --> G{1天内完成支付?}
    G -->|支付成功| P[支付成功页] --> I[订单待审核<br/>暂停计时]
    G -->|支付失败且未超时| G
    G -->|超时未支付| H[订单自动关闭] --> D
    I --> U[用户主动取消] --> L
    I --> J{管理员审核}
    J -->|通过| K[订单完成]
    J -->|驳回报名信息| E
    J -->|驳回并退款| L[自动退款]
    K --> M[推送支付成功消息]
    L --> N[推送通知<br/>退款预计3个工作日到账<br/>管理员驳回含原因]
    N --> D
```

### 模块职责

| 模块 | 职责 | 不负责 |
|------|------|--------|
| 用户系统 | 登录、实名、表单填写 | 订单状态、支付 |
| 订单系统 | 库存、支付、状态流转、退款 | 审核决策（判断通过/驳回） |
| 审核系统 | 管理员审核决策、驳回理由 | 改订单状态、退款、释放库存 |
| 通知系统 | 推送消息 | 业务逻辑 |

### 模块间交互

```
用户系统 ──创建──→ 订单系统
订单系统 ──待审核──→ 审核系统
审核系统 ──approve──→ 订单系统（→ completed）
审核系统 ──reject──→ 用户系统（重新填写）/ 订单系统（退款）
订单系统 ──事件──→ 通知系统
```

### 请求流转

```mermaid
sequenceDiagram
    participant Admin as 管理后台
    participant Review as 审核模块
    participant Callback as 回调实现
    participant Business as 业务模块

    Admin->>Review: POST /admin/reviews<br/>{target_type, target_id, action, comment}
    Review->>Review: 校验 target 存在性
    Review->>Review: 写入 review 记录
    Review->>Callback: 查找回调
    Callback->>Business: 执行业务操作
    alt identity.approve
        Business-->>Business: status = verified, verified_at = now
    else identity.reject
        Business-->>Business: snapshot 恢复, status = rejected
    else order.approve
        Business-->>Business: status = completed
    else order.reject
        Business->>Business: 微信退款 + sold库存退回available
        Business-->>Business: status = refunded
    end
    Callback-->>Review: 完成
    Review-->>Admin: Review 记录
```

### 回调注册表

| target_type | action | 回调 | 改动的表/服务 |
|-------------|--------|------|-------------|
| `identity` | `approve` | `identity_callbacks.approve` | `user_realname.status`, `verified_at` |
| `identity` | `reject` | `identity_callbacks.reject` | `user_realname` (snapshot 恢复) |
| `student` | `approve` | `student_callbacks.approve` | `user_student.status`, `verified_at` |
| `student` | `reject` | `student_callbacks.reject` | `user_student` (snapshot 恢复) |
| `enterprise` | `approve` | `enterprise_callbacks.approve` | `user_enterprise.status`, `verified_at` |
| `enterprise` | `reject` | `enterprise_callbacks.reject` | `user_enterprise` (snapshot 恢复) |
| `order` | `approve` | `order_callbacks.approve` | `order.status = completed` |
| `order` | `reject` | `order_callbacks.reject` | 微信退款, `order.status = refunded`, 已售库存退回可用库存 |

### 关键约束

1. **审核模块不 import 业务模块** — 回调通过注册表注入，编译期无依赖
2. **回调幂等** — 同一审核记录不应重复执行业务操作
3. **回调失败不影响审核记录** — 审核已写入，回调失败重试或人工介入
